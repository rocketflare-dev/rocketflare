# Agent runtime (D7, D17)

The pg-boss agent runtime ported onto Cloudflare Workflows. One table (`agent_runs`), one event log
(`agent_run_events`), one Workflow class (`AgentRunWorkflow`, `../../workflows/agent-run.ts`), one
registry. "Routes enqueue, never run."

| File | Role |
|---|---|
| `registry.ts` | `AGENTS: Record<AgentKey, AgentDefinition>`; `AgentDefinition = { meta: AgentMeta, run(ctx) }`; `AgentContext` (db, cfg, env, logger, tracer, tenantId, runId, userId, input, `emit`, `checkCancelled`, `chat { client, model, maxOutputTokens }`, `tools` (the built-ins, see below), `prompt(vars)`, `step(...)`) |
| `tools/` | Built-ins on `ctx.tools` (`buildAgentTools(ctx)` in `index.ts` — append app tools there), all tenant-scoped to the run and all answering JSON. `search-knowledge.ts`: `search_knowledge` = hybrid `searchChunks`, WHOLE passages (≤ `PASSAGE_MAX_CHARS` 4 000) inside a `RESPONSE_MAX_CHARS` 16 000 budget, grouped by document and located in it (`passage` n of `totalPassages`, `charOffset` → the `get_document` offset), default 8 hits; every answer carries `note` (the ranking is nearest-neighbour, NOT a relevance filter — dense search never returns nothing) and, when there is genuinely nothing indexed, `knowledgeBase` + a `hint`; no embeddings provider → `{ error: 'knowledge_search_unavailable', hint }`. `get-document.ts`: `get_document` = one document's text, `{ offset, maxChars ≤ 50 000 }` with `totalChars`/`returnedChars`/`hasMore`/`nextOffset`/`hint`; unknown, other-tenant, unconverted or failed → `{ error, hint }` (+ `knowledgeBase` for an unknown id). `list-documents.ts`: `list_documents` = what exists (indexed only), newest first, paged — `listKnowledgeDocuments` is the shared query the other two borrow for their dead ends. **Rule of thumb: a tool answer must be actionable — never a bare "nothing found", always what to do next.** |
| `examples/summarize-text.ts` | The single-call example: exclusive, precheck, one terminal tool via `callStructuredTool`, `step`/`tool.*`/`text` events, `recordUsage('agent:summarize-text')`, optional `ingestText` when `input.index` |
| `examples/research-topic.ts` | The agentic example: `runToolLoop` over `[...ctx.tools, submit_answer]` capped by `cfg.AGENT_MAX_TURNS`, `ctx.checkCancelled()` in `onStep` (the loop takes no `AbortSignal`), each `onEvent` → an `agent_run_events` row (tool results truncated). A loop ending WITHOUT the terminal call (`no_tool_call`/`max_turns` — Workers AI has no `tool_choice`) is salvaged by ONE `callStructuredTool` over the transcript, not failed; citations are filtered to the document ids the tools actually returned (titles from the search hit), so a hallucinated id is dropped. `recordUsage('agent:research-topic')` once, summed |
| `runs.ts` | `enqueueRun` (validate → insert `queued` → `AGENT_RUN_WORKFLOW.create({ id: runId })` → `instanceId`; partial-unique dedupe → `{ deduplicated: true }`; no binding → 503 `agent_runs_not_configured`), `claimRun` (`UPDATE … WHERE status IN (queued,running) RETURNING`, `attempt+1`), `finishRun`/`failRun`/`cancelRun` (only ever settle an ACTIVE row), `requestCancel(db, tenantId, runId, realtime?, env?)` (queued → cancelled; running → `cancelRequestedAt`; running AND already cancel-requested → FORCE: `instance.terminate()` best-effort, then settle `cancelled`), `reconcileRun` (`instance.status()` on read; `not_found` → failed; no binding → no-op), `appendEvent` + `nudgeRun` |
| `runtime.ts` | The three step bodies as plain functions: `claimStep`, `executeRun`, `finishStep`; `EXECUTE_RETRIES = 2`; error classification (`isRetryableRunError`: only `AiError` unavailable/rate_limit and DB-unavailable rethrow — and only while `attempt <= EXECUTE_RETRIES`) |

Rules:

- **Claim is the row, not the queue.** Every terminal write is `WHERE status IN ('queued','running')`; a retried step re-claims and a settled row is never rewritten.
- **Exclusive = the partial unique index** `agent_runs_active_exclusive_idx`. A non-exclusive agent needs that index relaxed (documented gap; every v1 agent is exclusive).
- **Cancellation is cooperative, then forced**: `requestCancel` sets the flag, the run's `checkCancelled()` polls between turns (and between tool results where the agent does the work in tools); `AgentCancelledError` is a TYPE the runtime maps to `cancelled`. A step in flight finishes. **The second cancel forces it** — terminate the instance, settle the row — because nothing polls in a hung model call or an orphaned instance, and an exclusive agent stuck `running` blocks the tenant. `reconcileRun` reads `terminated` as `cancelled`.
- **DB is the truth, WS is a nudge**: events go to `agent_run_events` first, then `entity.changed { entity: 'agent-run', id }`; viewers re-query `GET /api/agents/runs/:id`.
- **Per-agent model**: `resolveChat(..., { promptKey: meta.promptKey })` consults `agent_models`.
- **Every agent can read the knowledge base**: `ctx.tools` carries `search_knowledge` and `get_document` (everything indexed via `/documents` — pasted or uploaded — or an agent's `ingestText`). Pass `[...ctx.tools, ...ownTools, terminalTool]` to `runToolLoop`; a forced single-tool agent (`callStructuredTool`, like the example) simply does not use it. Never build a retrieval query from a model-supplied tenant id — the tool is bound to the run's tenant.
- The tool loop runs INSIDE one `execute` step (v1). Scaling path: one `step.do` per model turn with the transcript persisted between turns (`runToolLoop` already returns `messages`).
- Adding an agent: key in `@rocketflare/shared/ai/agents` (`AGENT_KEYS` + schemas) → prompt in `services/prompts.ts` → `examples/<key>.ts` → entry in `AGENTS`. No migration.
