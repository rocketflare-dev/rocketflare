## What changed

**An agent run can now stop and ask a person, resume on their answer, and be watched live on a page
of its own** (issues #17 and #7) — four schema changes and one new `[vars]` key.

The reasoning behind each decision is in `docs/CONCEPTS.md` §5 and §9; below is what changed and
what it costs you.

- **New contracts, appends only.** `ai/interrupts.ts` carries the four interrupt kinds (`approval ·
  choice · input · form`, closed), the typed `spec` union, `interruptPayloadSchema(spec)` — the ONE
  validator the route and the UI both call — `INTERRUPT_REJECTION`, a row schema with a **mandatory
  `key`**, the inbox and steering. `ai/artifacts.ts` carries five artifact kinds, where `document`
  and `file` hold **ids, never content**. `ai/agents.ts` appends `'awaiting_input'` LAST to the
  status schema, `ACTIVE_RUN_STATUSES` and the narrower `CLAIMABLE_RUN_STATUSES`, four event types,
  `AGENT_RESUME_EVENT`, `MAX_INTERRUPT_ROUNDS`, `AgentMeta.approvers` and
  `agentInfoSchema.inputJsonSchema`; `ai/agui.ts` gains four `kit.agent.*` CUSTOM events and
  `errors.ts` two 409 codes.
- **`AGENT_RESUME_EVENT` is `'agent-resume'` — a hyphen, on purpose.** Workflows event types allow
  only letters, digits, `-` and `_`; a `.` fails with `workflow.invalid_event_type`, which no Node
  suite catches and which first surfaces in production, on the first approval anyone gives.
- **Two new tables — migration.** `agent_run_interrupts` is one row per question asked, with a typed
  `spec` jsonb, and **`UNIQUE (run_id, key)` is the whole point**: a retried `execute` re-enters the
  agent from the top, and the index makes the second ask find the first ask's ANSWER.
  `agent_run_artifacts` is keyed `(run_id, key)` as an UPSERT so a redraft replaces itself.
- **Two changes to existing tables — migration.** The exclusive partial index is dropped and
  recreated over `('queued','running','awaiting_input')`, rendered from `ACTIVE_RUN_STATUSES` so
  index and list cannot drift, because **a parked run is still the active run for that agent**; the
  `CREATE UNIQUE INDEX` takes an `ACCESS EXCLUSIVE` lock. And `ai_usage` gains a nullable
  `agent_run_id`, `ON DELETE SET NULL`, that nothing writes yet, because per-run cost cannot be
  backfilled later.
- **`AGENT_INTERRUPT_TIMEOUT = "168 hours"`** is a new `[vars]` key in **both** tomls, passed
  verbatim to `step.waitForEvent`, so it must be a Workflows duration string rather than a number of
  seconds. **Instance retention is 30 days on Workers Paid and 3 on Free**, and past retention the
  resume event can never arrive.
- **The gate lives in the tool loop, never in a handler.** `Tool` gains `requiresApproval` /
  `requiresApprovalWhen` / `approvalMessage` / `allowEdits` / `onReject`, and `runToolLoop` gains
  `approvals`, `onInterrupt`, `runApproved` and `beforeTurn`. The gate scans the WHOLE turn before
  any handler runs, so a turn with three calls and one gate parks with nothing executed.
- **Three smaller rules in the tool loop, each a hang if missed.** `resumePendingToolCalls` runs
  before the `while`, because a parked checkpoint ends in unanswered `tool_use` blocks and sending
  one is a 400 on Anthropic. `runHandler` rethrows `InterruptRequested` and only that, or a
  handler-raised ask reads to the model as a failed tool and is asked again forever.
  `appendUserText` folds a steering note into a trailing user turn rather than opening a second
  consecutive one.
- **Two new services, and `agents/runs.ts` changes in six places.** `agents/interrupts.ts` has
  `requestInterrupt` (create-or-read on `(run_id, key)`), `resolveInterrupt` (one compare-and-set on
  `pending`, so two people answering at once is one 200 and one 409), `expireInterrupts` and
  `approvalsForRun`; `agents/artifacts.ts` has `upsertArtifact`. In `runs.ts`, `ACTIVE` is the
  imported wide list while `claimRun` alone stays narrow; **`parkRun` is not a `settle()`** —
  `finished_at` stays NULL and the checkpoint survives; `resumeRun` flips `awaiting_input →
  running`; `requestCancel` treats a park like `queued`; and `claimEffect` replays a *decision*
  where `runOnce` replays a *result*.
- **`nudgeOrRestartInstance` makes a lost instance recoverable**: `sendEvent`, and on
  `instance.not_found` a NEW instance `<runId>-r1`, `-r2`…, so **`agent_runs.instanceId` is *the
  latest* instance, not "the run id"**. `expireParkedRun` is the read-path net: asks past their
  deadline settle `cancelled` with `error` NULL. `AgentContext` gains `interrupt`, `steering`,
  `artifact` and `approvals`, and in the runtime's park arm **the order is the safety property** —
  rows first, then `parkRun`, since a parked run with no row is a hang.
- **`AgentRunWorkflow` becomes a loop**: `claim → execute#0 → [resume#0 → execute#1 → …] → finish`,
  or `expire#N` when nobody answers. **Every step name carries its round**, because a repeated name
  hands back the FIRST call's cached result, which reads as *"the agent ignored my approval"*.
  `resume#N`'s payload is ignored — the answer is already a row. **`finishStep` gains a second arm
  and the first did NOT change**: the failure backstop stays `queued | running`, or every parked run
  becomes a `failed` row. `InterruptDeclinedError` settles `cancelled` with **`error` NULL**, and
  `isRetryableRunError` answers false for both new types.
- **Three new routes, and `GET /api/agents` now carries each agent's `inputJsonSchema`.** `POST
  /runs/:id/interrupts/:interruptId`, `POST /runs/:id/steering` (409 on a settled run) and `GET
  /interrupts?status=pending` (the inbox, returning `canAnswer` per item rather than filtering).
  `inputJsonSchema` is an added field, but the run page's input summary and `formFor`'s middle rung
  **silently degrade to a JSON box without it**.
- **The resolve handler's order is the design.** Run visible → 404; caller is an approver → 403; ask
  belongs to the run → 404; payload validates → 400; compare-and-set → 409; an `interrupt.resolved`
  row; **then, only when nothing is still pending**, `resumeRun` and the wake. `resumeRun` before
  the wake is the only reason a restarted instance's narrow `claim` finds anything. `editedInput` is
  refused unless the ask offered `allowEdits`. Permissions add no CASL action and no subject:
  `canAnswer` is `update AgentRun` plus `AgentMeta.approvers`.
- **The projection takes the two tables it was missing** and stays pure, with the event row ids
  still the AG-UI ids. Every run emits a **`STATE_SNAPSHOT` right after `RUN_STARTED`** carrying
  `capabilities.humanInTheLoop`, and a parked run with pending asks ends in `RUN_FINISHED { outcome:
  { type: 'interrupt' } }`. **The tool-call pairing bug is fixed here too**: it keyed open calls by
  tool NAME, so two `search_knowledge` calls in one turn attributed BOTH results to the second; the
  runtime now writes `toolCallId` into `tool.start` and `tool.end`.
- **`GET /api/agents/runs/:id/agui/stream` (issue #7)** tails `agent_run_events` on one open
  connection, so a timeline fills in about 500 ms instead of three-second lumps. It is a GET so a
  client can use a bare `EventSource`, and `?afterSeq=` wins over `Last-Event-ID`. Four rules hold
  it together: the SSE `id:` goes on the LAST frame of a row's group and no other; **a read-stream
  failure emits no `RUN_ERROR`**, so closing with no terminal event means *reconnect*;
  `reconcileRun` runs once, at open; and no `: ping` frame on the protobuf wire. A parked run needs
  no code — the projector returns the interrupt outcome and the connection closes.
- **`reconcileRun` gained a liveness guard**, returning the row untouched, before the binding is
  touched at all, when the run wrote an event inside `RECONCILE_LIVENESS_MS` (30 s); the argument is
  **optional and opted into per call site**. And **`['agent-run-agui']` is deliberately absent from
  `REALTIME_INVALIDATIONS`**: the stream is its only writer, and the runtime nudges `entity:
  'agent-run'` on every row, so parking that list under the same root would discard what the stream
  just built.
- **A run stops being a modal and becomes a page.** `/agents/runs/:runId` keeps its URL and gains
  its own route, lazy chunk and breadcrumb; `RunDetailDrawer.tsx` and `AgentSteps.tsx` are
  **deleted**. **`runOwesAnswer(status)` is new and is `queued || running`** — `isRunActive` widened
  to include `awaiting_input` for the index, and the poll interval, runs list and status badge now
  read `runOwesAnswer`, so a parked run is **not re-fetched every three seconds for a week**.
- **The rest of the run workspace.** A 409 renders as *"Someone else answered this"* with no toast;
  `expiryState` picks its own tick rate; a non-approver sees one sentence, not disabled buttons;
  focus lands on the heading, never Approve. The timeline is `buildTimeline(events)` then
  `groupTimeline(rows)`, with two corrections that carry real bugs — **`tool.end` no longer
  overwrites `at`**, and it is **idempotent under duplicated events**. `outputFor(agentKey)` mirrors
  `forms/`, so **an agent is one input schema, one `forms/` entry and one `outputs/` entry**, and
  `fieldsFromJsonSchema` returns `null` for `$ref`, `allOf`/`anyOf`/`oneOf`, nested objects and
  arrays so the caller falls back to the JSON textarea WHOLE, never per field.
- **Finding what is waiting, and the stream stays additive.** `/agents?awaiting=1` is a URL with a
  chip; the SideNav badge is `NavItem.badgeKey` keyed `['agent-run','awaiting']`, **never polled**,
  and a dot when the nav is collapsed; `lib/notificationLink.ts` maps a notification to a path. The
  page is built against `GET /runs/:id` with `useRunStream` layered on for CADENCE only, so
  **deleting the hook leaves a working page**.
- **Both example agents now exercise the machine.** `summarize-text` raises an `approval` keyed
  `approve-index` before writing into the knowledge base, and wraps its summarise phase in
  `ctx.once` because a park is a retry boundary; it does **not** use `Tool.requiresApproval`, having
  no tool loop. `research-topic` raises a `choice` from INSIDE a tool handler and gates
  `index_finding` with `requiresApproval` + `allowEdits` + `onReject: 'tell_model'`. **A
  handler-raised ask must key on the QUESTION, not the call**, because it parks before the loop
  checkpoints that turn.

## How to apply

1. Take `packages/shared/src/ai/{interrupts,artifacts,agents,agui}.ts` and
   `packages/shared/src/errors.ts` as written — they are appends, so a copy that renamed its scope
   only translates the import specifier.
2. Take the schema changes: `'awaiting_input'` appended to `AGENT_RUN_STATUS_VALUES` in
   `apps/web/src/db/schema/agent-runs.ts` (**no DDL for the column** — it is `text`, which is
   exactly why it is `text`), the two new files for `agent_run_interrupts` and `agent_run_artifacts`
   each with a `tenantIsolation()` policy, the changed partial-index predicate on `agent_runs`, and
   the nullable `ai_usage.agent_run_id` with `ON DELETE SET NULL`.
3. Run `pnpm db:generate`, then **read the emitted SQL before applying it**: a *changed*
   partial-index predicate is the case drizzle-kit is weakest on, and a `CREATE` with no `DROP`
   silently leaves the old narrow index in place. Then `pnpm db:migrate`, and never copy the kit's
   `migrations/0011_*.sql`.
4. Add `AGENT_INTERRUPT_TIMEOUT = "168 hours"` to `config.ts`, `apps/web/.dev.vars.example` and
   `[vars]` in BOTH tomls. Keep the value under 3 days if you are not on Workers Paid, because
   instance retention is 3 days there and a park cannot outlive its instance.
5. Take `apps/web/src/api/services/ai/kit.ts` and the two new services
   `apps/web/src/api/services/agents/{interrupts,artifacts}.ts`, then merge
   `services/agents/runs.ts` by hand if you have touched it — the `ACTIVE` constant is now imported
   and `claimRun` alone keeps the narrow `CLAIMABLE_RUN_STATUSES`. A copy that COPIED `runToolLoop`
   rather than importing it gets none of the gate and should re-take the file.
6. Give any `AgentContext` implementation of your own — most likely a test double — the four new
   members `interrupt`, `steering`, `artifact` and `approvals`.
7. Take `apps/web/src/api/workflows/agent-run.ts` whole. If your copy forked the Workflow class,
   port the loop by hand and **keep the `#${round}` suffix on every step name inside it** — that is
   the one detail nothing in a Node suite can check for you.
8. Take the three new blocks in `apps/web/src/api/routes/agents.ts` and keep your own styling around
   them. Two edits there are NOT additive: `GET /runs/:id` and `/agui` must both go through
   `loadRun` so `expireParkedRun` runs on read, and `projectRunToAgui` takes a third argument — a
   call site that omits it still compiles and silently drops every ask and artifact from the
   timeline.
9. Take `apps/web/src/api/services/agents/agui-projection.ts` whole, because the tool-call pairing
   fix lives inside it and a partial merge that keeps the old name-keyed map silently mis-attributes
   parallel tool results. Then pass the model's `toolCallId` in both `tool.start` and `tool.end`
   from any agent of your own that emits them, and supply `lastSeq` wherever you hand-build an
   `AgentRunAguiResponse` (`routes/agents.ts` uses `events.at(-1)?.seq ?? 0`).
10. Take the stream client as new files plus one additive signature:
    `apps/web/src/ui/lib/runAguiStream.ts`, `hooks/useRunStream.ts`, the two `query-keys.ts`
    entries, and `readSse`'s second `onEvent` argument. **Do not add `['agent-run-agui']` to
    `REALTIME_INVALIDATIONS`** — every `agent-run` nudge would then discard what the stream just
    built, and the failure is silent.
11. Take `apps/web/src/ui/pages/agents/` wholesale — `RunPage.tsx` plus `run/**`, `outputs/**` and
    `fields/**` — and re-apply your styling, rather than merging hunk by hunk into
    `RunDetailDrawer.tsx` and `AgentSteps.tsx`, which are deleted.
12. Add `runOwesAnswer` to `apps/web/src/ui/hooks/useAgents.ts` and point `runPollInterval`,
    `useAgentRuns`'s `refetchInterval` and `RunStatusBadge` at it. **Do this even if you take
    nothing else from the UI**: with `awaiting_input` in `ACTIVE_RUN_STATUSES`, a parked run
    otherwise polls for days.
13. Make five mechanical UI edits outside that tree: `lib/format.ts` gains `formatDuration` /
    `runDuration` (they lived in the deleted drawer, which the runs table imported from);
    `lib/query-keys.ts` gains `agentRuns.awaiting`; `components/SideNav.tsx` gains `badgeKey` /
    `badgeTone` on `NavItem` resolved in the component, keeping `filterNavConfig` pure;
    `lib/notificationLink.ts` is added with its two call sites; and `Row` / `Section` / `formatCost`
    move from `pages/chat/ChatStatsPanel.tsx` into `components/ai/StatRows.tsx` — never into
    `components/shared`, the eager barrel `tests/config/ui-bundle.test.ts` guards.
14. Add an `awaiting_input` arm to any `Record<AgentRunStatus, …>` in your own UI. The kit's two use
    the label "Waiting for you" and the stylesheet's existing `awaiting-review` warning tone.
15. Read the diff rather than taking it for either example agent you kept and modified — the changes
    are an interrupt around the existing `ingestText` call, `ctx.once` around the existing model
    call, two `ctx.artifact` calls, and for `research-topic` two tool factories plus `approvals` /
    `runApproved` / `beforeTurn`. Update the `research-topic` prompt override in Settings → Prompts
    for any tenant that has one, or that tenant keeps the old text and the new tools go unused, and
    set `approvers: 'admin'` on an `AgentMeta` of your own if it touches money, customers or
    deletion.

## Conflicts to expect

- `packages/shared/src/ai/agents.ts` → several separate hunks (imports, the status enum, the
  event-type list, the event-payload block, `agentRunWithEventsSchema`, two new constant sections) →
  place your own statuses, event types or agent metadata by hand.
- `apps/web/src/ui/pages/agents/*` → two files deleted and a directory tree added → expect a
  wholesale reject in a copy that restyled the run surface, and take the tree fresh.
- `apps/web/src/api/services/agents/runs.ts` → the `ACTIVE` constant is imported now and `claimRun`
  keeps a narrower one → merge by hand if you touched either.
- Your own `AgentContext` implementation → four new members → add `interrupt`, `steering`,
  `artifact` and `approvals`.
- A hand-built `AgentRunAguiResponse` → gains `lastSeq` → supply `events.at(-1)?.seq ?? 0`.
- A UI test asserting a run's AG-UI sequence → `STATE_SNAPSHOT` is the second event of every
  projection now → update the expected sequence.
- Everywhere else the compiler names every missing arm; take the type error as the checklist.

## Verify

1. `pnpm lint && pnpm typecheck && pnpm test && pnpm build` exits 0.
2. `tests/config/agent-interrupts.test.ts` proves `AGENT_RESUME_EVENT` is a legal Workflows event
   type, the rejection semantics and the four payload validators;
   `tests/config/agui-contract.test.ts` proves the interrupt outcome round-trips over BOTH SSE and
   protobuf; `tests/api/rls-coverage.test.ts` proves both new tables are policied;
   `tests/config/wrangler-parity.test.ts` proves `AGENT_INTERRUPT_TIMEOUT` is in both tomls.
3. After migrating, `pg_indexes` shows the predicate as `WHERE status = ANY
   (ARRAY['queued','running','awaiting_input'])`.
4. The runtime suites: `agent-tool-loop-interrupt` proves the gate raises BEFORE any handler runs;
   `agent-interrupts` that a park keeps its checkpoint with `finished_at` NULL and that `sendEvent →
   not_found` creates `<runId>-r1`; `agent-run-workflow` that step names are distinct per round,
   that an unanswered park times out to `cancelled` with a NULL `error`, that `MAX_INTERRUPT_ROUNDS`
   stops a runaway agent and that `finishStep` does not fail a parked row.
5. The route and stream suites: `agent-interrupt-routes` proves the 409 on a double answer, the 403
   for a member under `approvers: 'admin'` who still sees the ask, the 400 for `editedInput` without
   `allowEdits`, and end to end that `sendEvent → not_found → <runId>-r1` completes the run;
   `agent-run-stream` proves 403 / 404 / 400 land before the first frame, that `?afterSeq=` wins
   over `Last-Event-ID`, that `id:` appears only on the last frame of each group, that a parked run
   emits the interrupt outcome and closes, that a body error emits NO `RUN_ERROR`, and that
   `reconcileRun` is called exactly once.
6. The UI suites: `run-timeline` and `run-page` cover the grouping, the start→end tool duration,
   idempotence, the whole-form fallback, `runPollInterval('awaiting_input') === false` and that an
   `agent-run` nudge leaves `['agent-run-agui']` untouched.
7. Follow `SETUP.md` §2.5 against `pnpm dev`: run **Summarise text** with *index the result* on,
   watch it park, answer it from a second browser as another member (one 200, one 409), and confirm
   the document appears in `/documents` **exactly once**. Then restart `pnpm dev` while a run is
   parked and answer it, which exercises the `sendEvent → not_found` restart path. `waitForEvent`
   runs only on the platform, so this walkthrough is the acceptance test for the durable park.
