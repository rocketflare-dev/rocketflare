## What changed

**The plugin contract becomes injected context with a version of its own, and deleting a tenant now
purges the R2 objects and plugin state the FK cascade cannot reach.** (D31; `docs/CONCEPTS.md` §16.)

- **`deleteTenant(db, tenantId, jobs, realtime?)` — new signature.** It proves the `JOBS_QUEUE`
  binding BEFORE the `DELETE` and enqueues a new `tenant.purge` job AFTER the row is gone; the job
  runs each plugin's new `hooks.onTenantDeleted(db, tenantId, env)` (best-effort, each try/caught)
  then deletes the R2 prefix `tenants/<id>/`, which no deleted organisation used to release. DO
  state is reachable only through DERIVED instance names, so one DO per ROW cannot be purged.
- **`StorageService` gains `listPage` and `deleteMany`**; `list` is a loop over `listPage`, so
  behaviour is unchanged, and paging keeps a large tenant out of a 128 MiB isolate.
- **The inbound plugin surface is injected context, not imported symbols** — the documented four
  entries measured as 128 (module, symbol) pairs across 55 kit modules. One context family now:
  `RequestCtx`, `JobCtx`, `CronCtx`, `ToolCtx`, `AgentCtx`, `WorkflowCtx`, `HookCtx`, `SeedCtx`,
  `DetachedCtx`, with methods replacing imports (`ctx.guard`, `ctx.uuid`, `ctx.page`, `ctx.enqueue`,
  `ctx.nudge`, `ctx.notFound`) and thin ADAPTERS over kit internals. `WorkflowCtx.step` hands a
  fresh per-step `db`; `ctx.durableObject(binding, tenantId, key?)` builds the id.
- **Three declared ENTRIES carry what cannot be injected**: `@/db/schema/kit` (a `pgTable(...)` runs
  at module scope and drizzle-kit reads it statically); the split UI kit — `@/plugins/api/ui-wiring`
  for `ui/index.ts`, which ships in the main bundle, `@/plugins/api/ui` for lazy pages; and
  `@testkit/integration` + `@testkit/unit`, aliased in `tsconfig.json` and `vitest.config.ts` and
  **deliberately not in `vite.config.ts`**. The unit builders **refuse a `db` not blessed by
  `setupTestDatabase`**, so there is no fast, database-free test of a data-touching handler.
- **`PLUGIN_API = { current, minSupported }`** (`packages/shared/src/plugins/contract.ts`, mirrored
  as `kit.pluginApi` in `.rocketflare.json`); a plugin declares `requires.pluginApi` as a whole
  number, compared as an integer. **Declared means strictly checked, undeclared means warned —
  permanently.** `docs/plugin-api.md` is generated by `scripts/plugin-api-doc.mjs`, committed and
  diff-checked: a changed or removed member with no bump to `current` fails, naming it.
- **A sixth barrel, `apps/web/src/plugins/worker-exports.ts`**, carries one `export *` per plugin,
  written by `pnpm plugin add|remove`, so **`workflow` and `durable_object` become provisionable**:
  `pnpm provision cloudflare <env>` writes `[[workflows]]` and `[[durable_objects.bindings]]` into
  BOTH tomls under the `-staging` rule, plus an append-only `[[migrations]]` tag `plugin-<id>-v1`
  using `new_sqlite_classes` or `new_classes` per the manifest's required `storage`. A DO binding's
  toml key is `name`, not `binding`; `d1`, `vectorize`, `analytics_engine` stay refused by name.
- **`pnpm plugin check` is now fifteen checks**, each failure formatted `<file>:<line> <what is
  wrong> — <the exact change>`, with `--json` separating `failures` from `warnings` and CI running
  the same command. New: the anchor is valid JSON; every manifest field; `requires.pluginApi`;
  `workerExports` in BOTH directions; a `durable_object` with no `onTenantDeleted`; a declared
  dependency missing from or contradicted by the host `package.json`; a tenant-isolation test when
  tenant-scoped tables are declared (that one proves a test EXISTS, not that it is right); and an
  installed version differing from the `defaultPlugins` pin. Every NEW rule warns for a plugin
  declaring no `requires.pluginApi` and fails for one that does.
- **Two plugins can no longer claim one table name**: `tableClashes` fails **unconditionally**,
  because neither plugin is wrong alone and a clash otherwise compiles cleanly. The prefix rule is
  corrected to the first hyphen-separated segment of the id (`example-feature` → `example_*`), a
  convention rather than something derived. Every source-scanning check now strips comments first.
- **A second installed plugin could not call `createRouter()` at module scope**, dying at import
  with `TypeError: (0 , createRouter) is not a function`. `accessScopeOf` moved to the leaf
  `api/services/access-sql.ts`, `access.ts` re-exports it, and `plugins/api/http.ts` imports it from
  the leaf.
- **`ctx.visibility.resolve` / `.set(kind, id, input)` / `.grantsFor(kind, ids)` on `RequestCtx`**
  publish what a plugin registering a restrictable resource had to reimplement — injected, not
  exported, because they dispatch through `VISIBILITY_RESOURCES`, which reads the plugin barrel. Two
  security properties ride on them: **every group id is checked against the tenant**, and **a member
  may share only with groups they are in** (403 `group_not_yours`). Known gap: `grantsForResources`,
  `setResourceGroups`, `resolveRequestedVisibility` stay unimportable. Also additive, so
  `PLUGIN_API.current` does not move: `ctx.groups` on `RequestCtx` / `DetachedCtx`;
  `activity_events`, `tenant_users`, `group_types`, `groupMembers` on `@/db/schema/kit`;
  `notifyUnauthorized` / `setUnauthorizedHandler` on `@/plugins/api/ui`; and `dispatchScheduled` /
  `SCHEDULED_TASKS` on `@testkit/integration`.
- **`pnpm kit:release` can cut a release again, and released history verifies again.**
  `resolveDefaultPlugin` could only `git ls-remote`, which cannot read a file out of a ref, so every
  release needed `--skip-plugin-check`; it now reads the manifest from the blobless mirror at the
  pinned ref. `.rocketflare.json` gains `retiredSurfaces`, without which `release-check --tag 0.2.0`
  failed on `feature-analytics`. Alongside: `requires` is REFRESHED from the manifest at the version
  being installed and checked BEFORE the patch applies; `coreEdits` are re-applied on upgrade and
  edits a new release no longer declares are reverted; `satisfies` accepts `||` and `>= 0.5.0`, a
  malformed range exits 6 rather than a generic 1, an undeclared `requires.kit` records `null`
  rather than `'*'`, the changelog check is anchored so `## 0.6.10` no longer satisfies `## 0.6.1`,
  a manifest shipping `"subdir": ""` no longer beats an explicit `--subdir`, and `satisfies` is now
  `satisfiesResult(version, range)` returning `{ ok, problem }`.
- **A repository may hold several plugins, released in lockstep**: `node scripts/release.mjs
  <version> --plugin <subdir>`, repeatable, stamping the root `package.json` plus EVERY
  `rocketflare-plugin.json` found by a bounded walk — a stale one makes every install report a
  version mismatch. `release-check.mjs` auto-discovers them and gained `behaviourFiles(changed, {
  within })`, without which the porting-note gate silently passed in a monorepo. `plugin-ci.yml`
  gains `kit_ref` and `plugin_subdirs`, unusable by a repository pinning `@main` until this release
  reaches the kit's default branch, and `notify-plugins.yml` dispatches `kit-released` on a tag.
- **"By hand" is retired as a phrase.** Every plan step is **declarative**, **agent** (an
  instruction plus `run`, `expect`, `assert`) or **human**, and `--json` carries `kind` per step.

## How to apply

No migration and no schema change. `pnpm plugin check` after upgrading is the fastest way to find
what this release asks of a plugin you own: every failure carries its own fix. A reported
dependency clash is a WARNING rather than a failure — the host and the plugin disagree on a
package range, and you decide which manifest moves.

1. Update every `deleteTenant` call site to `deleteTenant(db, tenantId, jobs, realtime?)`, passing
   `c.env.JOBS_QUEUE` third. The kit has one, `apps/web/src/api/routes/tenant.ts`.
2. If you implement `StorageService` yourself, add `listPage` and `deleteMany` — and give a test
   double REAL cursor semantics, or a broken paging loop looks correct.
3. If you removed `JOBS_QUEUE`, keep your own R2 cleanup on the delete path: purging went with it.
4. Move any retired-surface exemption in `apps/web/tests/config/upgrade-notes.test.ts` into the new
   `retiredSurfaces` key in `.rocketflare.json`, and delete the local list.
5. If your own scripts call `satisfies(version, range)`, change them to `satisfiesResult(version,
   range)` and read `{ ok, problem }`.
6. If you own no plugin, stop here; `example-feature` is the migrated worked example.
7. Add `"requires": { "pluginApi": "1" }` to each of your plugins' `plugin.json`; until you do, the
   new checks warn rather than fail and nothing verifies that plugin.
8. Convert each plugin's entry points to the context family: routes `RequestCtx`, job handlers
   `JobCtx`, cron tasks `CronCtx`, tools `ToolCtx`, Workflows `WorkflowCtx`, hooks
   `HookCtx`/`SeedCtx`.
9. Annotate the context explicitly — `const ctx: RequestCtx = requestCtx(c)`. `ctx.notFound(...)`
   returns `never`, and TypeScript narrows on that only when the call target is annotated, so an
   inferred `const ctx` throws at runtime while the compiler believes the row may be undefined.
10. Change each plugin schema file to import `@/db/schema/kit` **by relative path** — drizzle-kit
    bundles that file itself and resolves no tsconfig alias.
11. Change each plugin's `ui/index.ts` to import only `@/plugins/api/ui-wiring`, its lazy pages to
    import `@/plugins/api/ui`, and its tests to import `@testkit/integration` / `@testkit/unit`.
12. For a plugin shipping a Durable Object or Workflow class, add all four:
    `src/plugins/<id>/worker-exports.ts` re-exporting the classes, those names in the manifest's
    `workerExports`, `storage` on each `durable_object` binding, and `hooks.onTenantDeleted`.
13. For a plugin registering a restrictable resource, replace any reimplementation of the visibility
    helpers with `ctx.visibility.*`, keeping the tenant check and 403 `group_not_yours`.
14. For anything that narrows by group TYPE, read `ctx.groups` (or `ctx.detached().groups`); a test
    that puts somebody in a group imports `groupMembers` from `@/db/schema/kit`.
15. For a plugin with a cron task, assert the expression and the task met with `dispatchScheduled`
    from `@testkit/integration`, checking `status: 'ok'` — a task that threw returns `'failed'`.
16. Remove any deferred-initialisation workaround in a plugin (routers built on first read, `mounts`
    as a getter): the module cycle that forced it is fixed.
17. Run `pnpm provision cloudflare <env>` once per environment for a plugin declaring bindings,
    crons, prefixes or vars. The toml editing disappeared; running the command did not.
18. Compare your own plugins' table names against each other, and correct any local documentation
    repeating the old "`<id>_*` with the hyphens dropped" rule.
19. Changing a MEMBER of any declared entry: run `node scripts/plugin-api-doc.mjs`, commit
    `docs/plugin-api.md`, and bump `PLUGIN_API.current` in `plugins/contract.ts` and
    `.rocketflare.json`.
20. To release a repository holding several plugins, run `node scripts/release.mjs <version>
    --plugin <subdir>` (repeat per plugin) then `node scripts/release-check.mjs --tag <version>`.
21. For kit-release notifications: a PAT as `PLUGINS_DISPATCH_TOKEN` (Contents, Metadata: read), the
    repos named in `notify-plugins.yml`, and `repository_dispatch: [kit-released]` on each.

## Verify

1. `pnpm lint && pnpm typecheck && pnpm test && pnpm build` green, with `git status --porcelain
   apps/web/worker-configuration.d.ts` empty.
2. Delete a tenant owning an uploaded file, then `wrangler r2 object list <app>-files --prefix
   "tenants/<id>/"` returns nothing. Under `wrangler dev` the terminal logs `tenant.purge: removed N
   object(s)`, and running the job again must delete 0 and still ack.
3. `node scripts/release.mjs <next> --dry-run` passes WITHOUT `--skip-plugin-check`, and `node
   scripts/release-check.mjs --tag 0.3.0` no longer reports `feature-analytics`.
4. Append `import { tenantIsolation } from '../../../db/schema/rls'` to any plugin file: `pnpm
   --filter @rocketflare/web test:config` must fail naming the file, the line and the replacement
   import.
5. Check the bundle boundary on BOTH builds: `import '@testkit/integration'` under
   `apps/web/src/ui/` must FAIL `build:ui`, while the same import under `apps/web/src/api/` SUCCEEDS
   under `build:api`, so there the source scan in `tests/config/plugins.test.ts` is the only
   protection.
6. `pnpm plugin add <a plugin declaring workerExports> --apply`, `pnpm plugin remove <id> --apply`,
   then `git diff --exit-code apps/web/src/plugins/worker-exports.ts` — byte-identical, including
   the restored `export {}` marker. Then delete a member from any context (say `RequestCtx.uuid`):
   `node scripts/plugin-api-doc.mjs` exits 3 naming it, and running it twice leaves no diff.
7. Point `pnpm plugin check` at a deliberately broken plugin (a bad manifest value, a
   `workerExports` name nothing exports, a `durable_object` with no `onTenantDeleted`, a missing
   isolation test): each failure names the file and the exact edit; `--json` reports the same.
8. Prove the cycle fix with a SECOND plugin installed (one never shows it): add a plugin declaring
   `visibilityResources`, `pnpm db:generate --name plugin-<id>-check && pnpm db:migrate`, then `pnpm
   test` — a route calling `ctx.visibility.set` must not die at import. Use a DEDICATED Postgres,
   not the shared `:5433`; reset that only with `docker compose -f apps/web/docker-compose.test.yml
   down -v`.
