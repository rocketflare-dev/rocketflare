## What changed

**The kit gained the seam a plugin plugs into (D31): five barrels, closed registries reopened as
`CORE_X`, `pnpm plugin` as the lifecycle, and the demo feature re-shipped as the reference plugin —
an app with no plugins behaves as before.**

- **Five barrels**, each exporting an `as const` tuple AND a widened list beside it (an empty tuple
  indexes to `never`): `packages/shared/src/plugins/index.ts`,
  `apps/web/src/plugins/{server,ui,schema}.ts` and `apps/cli/src/plugins/index.ts`. An install is
  those five lines, a surface entry and one `pnpm db:generate`. Wired slots: `mounts`,
  `apiPrefixes`, routes, nav, settings tabs, query keys, config, both tenant hooks and
  `realtimeRoots`.
- **Closed sets reopened, public name unchanged** — the kit's literal becomes `CORE_X` and `X =
  [...CORE_X, ...plugin X]`, so nothing that READS one moves and only where you ADD to it does:
  `CORE_JOB_VARIANTS` (from which both unions, `JobType` and `JOB_TYPES` derive), `coreHandlers`,
  `CORE_AGENT_KEYS`, `CORE_AGENTS`, `CORE_AGENT_FORMS`, `CORE_PROMPT_REGISTRY`, `CORE_FEATURES`,
  `CORE_FEATURE_FLAGS`, `CORE_SCHEDULED_TASKS`, `CORE_UNSCOPED_ALLOWLIST`, `CORE_QUERY_KEYS`,
  `CORE_NAVIGATION`, `coreConfigSchema` and `PluginSubject`, with `ServerPlugin.grants` after the
  kit's matrix.
- **`runHandler` is DELETED**: the mapped handler table already proves completeness for a set the
  kit cannot enumerate, so dispatch is `handlers[job.type](job as never, ctx)`. **`DeclaredBy<P,
  K>`** narrows a barrel union to members that DO declare an optional field — without it, installing
  a plugin with no agents was a compile error for every other plugin.
- **Visibility (D29) is now a registry.** `services/access.ts` exports `VisibilityResource` (`{ key,
  noun, usageKey, predicate, setGroups, grantRows, countGrants }`) and `VISIBILITY_RESOURCES`;
  documents and analytics pages are two entries, a plugin adds its own through
  `ServerPlugin.visibilityResources`, and `setResourceGroups` / `grantsForResources` dispatch on a
  `kind`. `countGroupGrants` MOVED to `access.ts` to avoid a cycle.
- **`.rocketflare.json` learns `kind: 'plugin'`** with a `source` block naming the repository a
  plugin came from, and `readManifest` (`scripts/lib/manifest.mjs`) is the one kit-vs-app predicate
  and the one reader of the git-ignored `.rocketflare.local.json` sidecar, where a `--local` install
  is recorded. `classifyPath` gains `skipped-plugin-owned`.
- **Two measured constraints.** `packages/shared/src/plugins/**` never imports one of the five
  composers (`ai/agents.ts`, `jobs.ts`, `permissions.ts`, `features.ts`, `realtime.ts`) AT RUNTIME —
  two zod modules in a cycle crash at module evaluation; a whole-declaration `import type` is fine,
  `import { type X } from` is not. And a plugin declares `relations()` for its OWN tables only: a
  second one for a core table silently strips `with:` app-wide.
- **`example-feature` is now a PLUGIN** — three directories and five barrel lines — and is meant to
  be deleted. Its flag entry, guard, route, nav item, page, job variant, handler and demo seed row
  moved into it, and the job is renamed **`example.ping` → `example-feature.ping`**. It gained an
  `example_notes` table, a CRUD mount behind `requireFeature`, `onTenantCreated`, an agent tool and
  two CLI commands. **`CORE_FEATURES` is now EMPTY**, so `featureNameSchema` is a refined
  `z.string()`.
- **`scripts/plugin.mjs` (`pnpm plugin`) is the lifecycle**: `add <repo|path>[@ref] [--subdir]
  [--local] [--apply]`, `upgrade`, `remove [--archive]`, `list`, `check`, `export`. Exit codes 0 · 1
  error · 2 usage · 3 unreachable · 4 rejects · 5 no manifest · 6 requirement unmet · 7 target
  exists. Every command refuses a dirty tree (`--allow-dirty`) and **none applies anything without
  `--apply`**. It never copies a migration (the host runs `pnpm db:generate`), never edits a
  wrangler toml, and refuses any file outside the plugin's four roots.
- **A VENDORED plugin is the kit's**: `source.repo` equal to the kit's own repository with no
  subdirectory makes `plugin upgrade` defer to `pnpm kit:upgrade` and skips `requires.kit`.
  **`kit:upgrade`** exits **6** when the target kit version leaves a plugin's `requires.kit` range
  (`--force` to proceed), annotates a change to a file in a plugin's `registries[]` as
  `touches-plugin-registry`, and warns when the target ref is an ANCESTOR.
- **Provisioning learns a plugin's platform declarations (decision 12).** New
  `apps/web/scripts/provision/plugin-resources.ts` owns the naming rule
  (`<app>-<id>-<name>[-staging]`, `<APP>_<ID>_<NAME>[_STAGING]` for KV) and supports `kv`, `queue`,
  `r2`; anything else is a loud refusal naming the type. `plugin.json` gains `bindings[]`,
  `crons[]`, `apiPrefixes[]` and `vars[]` (`secret: true` = a Worker secret), and `provision
  cloudflare <env>` writes into BOTH tomls.
- **CI proves the kit against the plugins a fresh clone installs (decision 5).** The gate moved into
  a reusable `.github/workflows/gate.yml`, and `ci.yml` calls it twice — plain, and again with every
  `defaultPlugins` entry installed at its pinned ref, then `pnpm db:generate` and `pnpm
  db:migrate:ci`. Entries are OBJECTS (`{ id, repo, ref?, subdir? }`); `plugin-ci.yml` is the mirror
  a PLUGIN repository invokes in three lines; `kit:release` refuses a version its default plugins
  are not ready for.
- **`/rf-plugin` is a new skill**, every other skill learned about plugins, and
  **`scripts/bootstrap.mjs` gained a `plugins` step and `--no-plugins`, taking it to TEN steps** —
  `6 plugins`, `7 seed`, `8 cloudflare`, `9 cli`, `10 run`. It reads `defaultPlugins`, skips ids
  already recorded, installs the rest and migrates, BEFORE the seed so a plugin's demo-data hook is
  in place. `CONCEPTS.md` gains §16 and `SETUP.md` §1.4b.
- **Twelve lifecycle fixes, found by running export → remove → add for real.** The three fixed
  filenames are built from `KIT.slug` and are `KIT.preserved` in `rename.mjs`, so a renamed copy no
  longer looks for `.acme.json`; `remove` writes `export {}` into the schema barrel, without which
  removing the last plugin left a SCRIPT and TS2306; `unsupportedForKit` makes `kit:upgrade` honour
  the vendored exemption; and the `git ls-files` scanners filter by `existsSync`.

## How to apply

Take the new files whole (`packages/shared/src/plugins/*`, `apps/web/src/plugins/*`,
`apps/cli/src/plugins/*`, `scripts/plugin.mjs`, `scripts/lib/{manifest,git-lib,plugin-lib}.*`,
`apps/web/scripts/provision/plugin-resources.ts`, the test files) plus the edits to the wiring
points above. No new dependency and no toml change.

1. Add a `./plugins` export entry to `packages/shared/package.json`, beside `./ai`. The wildcard
   `./*` maps to a FILE, so `@rocketflare/shared/plugins` does not resolve without it.
2. Add `.rocketflare.local.json` to `.gitignore`, or a plugin installed with `--local` is committed
   and every copy made from that commit inherits wiring for files it does not have.
3. Add `"plugin": "node scripts/plugin.mjs"` to the root `package.json`, which is `manual`.
4. Confirm `.gitignore` still covers `.upgrade/` — the plugin mirrors live there too
   (`.upgrade/plugins/<repo>.git`, `.upgrade/plugins/work/<id>/<ref>/`).
5. Add `defaultPlugins` to `.rocketflare.json` by hand (that file is never ported). `[]` is correct
   until you list one; an entry is `{ "id", "repo", "ref"?, "subdir"? }`.
6. If you added your own job types, move each variant into `CORE_JOB_VARIANTS` as ONE entry (not
   two), delete your literal from `JOB_TYPES` (derived now), keep your handler entry in
   `coreHandlers`, and **delete your `case` from `runHandler`** — that function is gone.
7. If you added your own agents, feature keys or crons, the literal you were editing kept its
   contents and changed its name (`CORE_AGENT_KEYS`, `CORE_AGENTS`, `CORE_PROMPT_REGISTRY`,
   `CORE_AGENT_FORMS`, `CORE_FEATURES`, `CORE_FEATURE_FLAGS`, `CORE_SCHEDULED_TASKS`).
8. If you customised the D29 visibility helpers, re-express your resource as a `VisibilityResource`
   entry rather than a third branch; `visibleDocuments` / `visibleAnalyticsPages` keep their
   signatures as the two core `predicate`s, so the SQL is unchanged.
9. If you kept the demo feature in your own `CORE_FEATURES`, `App.tsx`, `SideNav.tsx` and `jobs.ts`,
   either take the plugin whole and delete your copies, or keep yours and skip the plugin.
10. If you enqueue `example.ping` anywhere, change it to `example-feature.ping`, which exists only
    with the plugin installed. The old type fails `jobInputSchema` at the producer.
11. Generate the migration yourself — the kit's own `0012_plugin-example-feature-0.1.0` is NOT
    ported. With the plugin's files and the schema barrel line in place, run `pnpm db:generate
    --name plugin-example-feature-0.1.0 && pnpm db:migrate`; expect one `CREATE TABLE
    "example_notes"`.
12. If you wrote your own helper around `scripts/upgrade.mjs`, re-point it: `ensureMirror`,
    `collectChanges`, `collectRenames`, `notesBetween` and the artifact writer now come from
    `scripts/lib/git-lib.mjs`, and `ensureMirror` RETURNS the mirror handle.
13. If you customised `ci.yml`, move your extra steps into `gate.yml` and keep `ci.yml` as the
    caller, or the second pass will not run your steps.
14. For a plugin needing KV, a queue or a bucket, add its `bindings[]`, `crons[]`, `apiPrefixes[]`
    and `vars[]` to `plugin.json`, run `pnpm provision cloudflare <env>` per environment, then `pnpm
    types` and commit `worker-configuration.d.ts`.
15. If you hand-patched `MANIFEST_FILE` or `PLUGIN_MANIFEST_FILE` back to a literal, drop that
    patch, and check `.gitignore` still contains a line reading exactly `.rocketflare.local.json`.
16. If you publish plugins of your own, point each plugin repository at `plugin-ci.yml` with the
    three-line caller in `docs/DEPLOY.md`.

## Conflicts to expect

- `packages/shared/src/jobs.ts` → the two hand-written unions became one `CORE_JOB_VARIANTS` tuple
  and `JOB_TYPES` is a derivation → an app with its own job types rejects here; step 6 is the fix.
- `apps/web/src/api/queues/jobs.ts` → `runHandler` is deleted and `handlers` is two merged objects →
  a `case` of your own has nowhere to go back to.
- `apps/web/src/api/services/access.ts`, `services/groups.ts`, `api/routes/groups.ts` → the two
  helpers lost their `if (kind === 'document')` branches and `countGroupGrants` moved → re-express
  as a registry entry with a `usageKey`; the 409 type is now `Record<string, number>`.
- `ui/lib/query-keys.ts`, `ui/components/SideNav.tsx`, `src/config.ts`, `api/services/prompts.ts`,
  `api/services/agents/registry.ts`, `ui/pages/agents/forms/index.ts`, `api/scheduled.ts`,
  `packages/shared/src/{permissions,features}.ts` → a literal renamed `CORE_*` → edits apply
  cleanly.
- `apps/web/src/ui/App.tsx`, `SideNav.tsx`, `ui/lib/feature-guards.ts`,
  `api/queues/handlers/example-ping.ts`, `apps/web/scripts/seed.ts` → the example route, nav item,
  const, handler and demo flag row are deleted → take the deletions; if you edited the nav there,
  remove your copy by hand.
- `apps/web/tests/config/unscoped-allowlist.test.ts`, `tests/api/rls-coverage.test.ts`,
  `tests/api/{chat,chat-tools,agent-research,agent-tools}.test.ts` → the first two gained a union
  with installed plugins, the rest became prefix assertions.
- `scripts/upgrade.mjs` → about 120 lines of git plumbing are gone and call sites use a mirror
  handle → move a local edit into `scripts/lib/git-lib.mjs`.
- `scripts/release.mjs`, `scripts/release-check.mjs` → `main` reads a `releaseContext()` and stamps
  a LIST of version files → an app that taught it to bump another file adds an entry to that list.
- `apps/web/scripts/provision/patch-toml.ts`, `cf-provision.sh`, `wrangler-parity.test.ts` →
  `patchBindingId` is renamed `patchBindingKey` and takes the key (`id` / `queue` / `bucket_name`);
  the four creation blocks became `ensure_*` functions → re-apply on the new signature.
- `.github/workflows/ci.yml` → rewritten as a caller of the new `gate.yml` → merge by hand;
  `deploy.yml` gains only a comment.
- `scripts/bootstrap.mjs` → TEN steps, renumbered from `seed` onwards → take `planDefaultPlugins`,
  `TOTAL_STEPS = 10`, `--no-plugins` and `stepPlugins`; check nothing still prints `n/9`.
- `.rocketflare.json`, root and shared `package.json`, `.gitignore`, `SETUP.md`, `README.md`,
  `CLAUDE.md`, `.claude/skills/**` → `manual` or never ported → apply steps 1–5 by hand.
