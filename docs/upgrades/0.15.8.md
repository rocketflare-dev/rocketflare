## What changed

The kit's own tests now live in `apps/web/tests/kit-only/`, which the rename deletes and the upgrade never ports, so a copy's gate no longer fails on the kit's version chain.

- `apps/web/tests/kit-only/`: new; the `kit-only` vitest project, registered only while the directory exists. See `docs/CONCEPTS.md` §13.
- Moved there from `apps/web/tests/config/`: `upgrade-notes`, `release-lib`, `release-root`, `rename-lib`, `rename-safe-identifiers`, `nudge-hooks` and `plugin-ci` (`.test.ts`). `upgrade-notes` asserted the root version equals the kit version, which fails in every copy that has released.
- `apps/web/tests/config/kit-manifest.test.ts`: split. The kit-state claims (version pin, anchors on disk, the tooling the kit ships) moved to `tests/kit-only/kit-manifest.test.ts`. The part that stays adds "kit-only tests are not in this copy, and not wired into its gate".
- `.rocketflare.json`: new `kitOnly` list (`apps/web/tests/kit-only/**`). `apps/web/tests/config/rename-lib.test.ts` has left `neverPort`.
- `scripts/lib/upgrade-lib.mjs`: new `KIT_ONLY_PATHS`, `KIT_ONLY_PROJECT`, `kitOnlyGlobs()` and `stripKitOnlyWiring()`. `classifyPath` returns `skipped-kit-only` for a kit-only path before any other rule, including under `--include-kit-tooling`.
- `scripts/upgrade.mjs`: also honours the TARGET kit's `kitOnly` list, read from the mirror.
- `scripts/rename.mjs`: deletes every kit-only file first and drops `--project kit-only` and `test:kit-only` from the package.json scripts.
- `apps/web/package.json` (kit): `test:isolated` and `test:ephemeral` run `--project kit-only`; new `test:kit-only`.
- `.github/workflows/gate.yml`: the renamed-copy pass fails if a kit-only file or `--project kit-only` survives the rename, and runs the gate at root version `1.2.3`.

## How to apply

1. Run `pnpm kit:upgrade --to 0.15.8 --apply` on a clean tree, as for any release.
2. Delete the `apps/web/tests/kit-only/` directory the 0.15.7 upgrader wrote as added files (it predates `kitOnly`): `rm -rf apps/web/tests/kit-only`.
3. Delete the kit's own tests from their old place: `git rm --ignore-unmatch apps/web/tests/config/upgrade-notes.test.ts apps/web/tests/config/release-lib.test.ts apps/web/tests/config/release-root.test.ts apps/web/tests/config/rename-lib.test.ts apps/web/tests/config/rename-safe-identifiers.test.ts apps/web/tests/config/nudge-hooks.test.ts apps/web/tests/config/plugin-ci.test.ts`. The upgrade lists these seven as `deleted` and leaves them in place without `--apply-deletes`.
4. Take the kit's `apps/web/tests/config/kit-manifest.test.ts` whole. It drops the `it.skipIf(!isKit)` cases and adds the `kit-only tests` block.
5. Take the kit's `apps/web/vitest.config.ts` change, the `KIT_ONLY_DIR` constant and the conditional `kit-only` project. It registers nothing in a copy.
6. Take the kit's `scripts/lib/upgrade-lib.mjs`, `scripts/lib/upgrade-lib.d.mts` and `scripts/upgrade.mjs` untranslated. All three are on the rename's exclusion list.
7. In `.rocketflare.json` (never ported), add `"kitOnly": ["apps/web/tests/kit-only/**"]` after `neverPort`, and remove `"apps/web/tests/config/rename-lib.test.ts"` from `neverPort`.
8. Leave `apps/web/package.json` as it is (`manual`). A copy never runs `--project kit-only` and has no `test:kit-only` script, so do not add the kit's.
9. `.github/workflows/gate.yml` is `manual`. The new rename assertions run only in the kit's own repository (ci.yml's `renamed` job), so a copy may skip them.
10. If the copy has its own test that asserts something true only of the kit, delete it or rewrite it for the copy. One example is a test that reads the root `package.json` version against `.rocketflare.json`'s `kit.version`.

## Conflicts to expect

- `apps/web/tests/config/kit-manifest.test.ts` → split into the kit-only half and the universal half → take the kit's file, then re-add any assertion the copy wrote itself.
- `apps/web/tests/kit-only/**` → written as added files by the 0.15.7 upgrader → delete the directory (How to apply, step 2).
