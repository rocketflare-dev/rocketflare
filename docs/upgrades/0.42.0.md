## What changed

Field-report fixes: new apps start with `/rf-start` and a design conversation (`/rf-design`, rendered by `pnpm design:docs`), `pnpm plugin list --available` shows what already exists, setup handles WSL, and plugins gain four missing seams.

- `bash scripts/bootstrap.sh` knows WSL2 (`scripts/lib/prereqs.sh`). Run as root in WSL, it prints the `adduser` and `wsl -d <distro> -u <name>` steps. With `docker` missing inside WSL, it says to turn on Docker Desktop's WSL integration, then quit and restart Docker Desktop. With no fnm or nvm, it prints the documented nvm install. A `node`, `corepack`, `pnpm` or `docker` that resolves under `/mnt/<drive>/` (Windows' PATH leaking in) is ignored. pnpm is installed with the active Node's own corepack if it ships one, else with its `npm` (Node 26 ships no corepack). `SETUP.md` has a "Windows (WSL2) — before you start" block.
- `pnpm seed` labels its credentials as local demo values. The API key prints on one line labelled `api key:` with a "local demo key … safe to discard" note under it. The invite URL prints as a `local demo link (this machine only)`. `extractSeedKey` (`scripts/lib/bootstrap-lib.mjs`) reads the labelled line and still accepts the old banner.
- The seeded dev accounts are now one list: `DEV_ACCOUNTS` in `apps/web/src/ui/lib/dev-accounts.ts` (`{ email, name, role, isGlobalAdmin? }`). `scripts/seed.ts` reads it, and so do the login page's quick-login buttons and its `?as=` allow-list (now case-insensitive). `--demo` finds the admin and member accounts by role, not by position.
- Roles reach the screen through `roleLabel(role)` / `ROLE_LABELS` in `@rocketflare/shared/tenants` instead of the raw value styled with CSS `capitalize`. This covers `RoleBadge`, the role pickers (invite, People, approve request), the user menu, Home and the pending-invitations banner. Visible text is now `Owner` / `Admin` / `Member` / `Support`.
- Plugin seam: `RequestCtx.apiKeyId` (on `PluginAuth`) is the id of the API key a Bearer request came in on, `null` for a session, and never the secret (`apiKeyIdOf(auth)` in `api/auth/api-key-session.ts`). `makeRequestCtx` accepts `apiKeyId`.
- Plugin seam: a `settingsTabs` tab can carry a `guard` (`PluginSettingsTab`, exported from `@/plugins/api` and `@/plugins/api/ui-wiring`). `SettingsLayout` and `navigationEntries` check it with `useNavGuard`, so `{ feature: 'x' }` hides the tab in an organisation without the flag.
- Plugin seam: `ServerPlugin.hooks.seed` runs on every `pnpm seed`, with or without `--demo`, before the demo data. `PluginSeedContext` (and `SeedCtx`, where it is optional) gains `setFeature(key, enabled = true, tenantId = seeded tenant)`, which writes a per-organisation override (an unknown key throws). `pnpm seed --feature <key>[=on|off][@<tenant-slug>]` (repeatable) writes the same override after the hooks and the demo (`apps/web/scripts/lib/seed-features.ts`). Rationale: `docs/CONCEPTS.md` §16 "Hooks".
- `scripts/plugin.mjs` gains `list --available [--json]`: one line per plugin (id, version, installed here or not, description), read through the same mirror `add` uses with the fetch made mandatory; unreachable is one `error:` line and exit 3, never a cached list ([CONCEPTS §16](../CONCEPTS.md#16-plugins)).
- Commercial plugins (`rocketflare-dev/rocketflare-commercial-plugins`) appear under their own heading with a `licence:` line only when the person's git credentials can read that repository; otherwise nothing is printed about them.
- `scripts/lib/plugin-lib.mjs` gains `PLUGIN_CATALOGUES`, `catalogueEntries`, `catalogueReads`, `readmeLede`, `licenceTerms`, `renderCatalogue` and `catalogueJson`; `scripts/lib/git-lib.mjs` `ensureMirror` gains `fresh` and `quiet` options and a mirror gains `prefetch(ref, paths)`.
- `/rf-plugin add` with no id shows the catalogue instead of asking for a repository; `/rf-how-do-i` §0 first asks "does a plugin already do this?".
- The rename preserves `rocketflare.dev/plugins` (`KIT.preserved` in `scripts/lib/rename-lib.mjs`), so a renamed copy still points at the published catalogue page; an existing copy has already been renamed and needs nothing.
- `SETUP.md` §2.7 no longer pins a plugin release in its example (no `@ref` reads the newest tag), and SETUP, CONCEPTS §8/§16 and `/rf-setup` point at `pnpm plugin list --available` and https://rocketflare.dev/plugins.
- `/rf-design` (new, `.claude/skills/rf-design/`): the shape questions (organisations, roles and words, AI, money, non-functional needs, hosting, licence, integrations and existing plugins), stages with "Done when", the brand step, and an independent review. It writes `docs/design/`. Rationale: `docs/CONCEPTS.md` §13 "A copy starts with a design".
- `/rf-start` (new): detach, setup, `/rf-design`, `/rf-adapt`, in that order; the website's prompt names it.
- `scripts/detach.sh` (new): the one detach. It stamps only the kit block's `commit` in `.rocketflare.json`. `install.sh` used to stamp the vendored example plugin's `source.commit` too, and `/rf-setup` §0 and the README's by-hand path stamped nothing.
- `/rf-adapt` checklist row (e) applies `docs/design/brand.css` when there is one, and the new row (h) writes the app's own `LICENSE`. The kit's MIT notice moves into `LICENSES/kit-MIT.txt`, a new `neverPort` path.
- `scripts/design-docs.mjs` builds `docs/design/html/` from `docs/design/*.md` and inlines a sanitised `docs/design/diagrams/*.svg`; `--open`, `--check`, `--contrast`, `--apply-brand` (`docs/CONCEPTS.md` §7).
- The contrast floors and pairs moved from `apps/web/tests/ui/contrast.test.ts` into `scripts/lib/contrast.mjs`, which the test and `--contrast` share.
- New libraries: `scripts/lib/brand.mjs`, `scripts/lib/markdown-lite.mjs`, `scripts/lib/svg-sanitize.mjs`, `scripts/lib/design-docs-lib.mjs`, each with a `.d.mts`.
- `docs/DEPLOY.md` "Running somewhere other than Cloudflare": the kit is designed for Cloudflare; to run elsewhere, start from Rocketpod, which often lags behind in features.
- `apps/web`'s `typecheck` runs tsc with a 4 GB heap (`node --max-old-space-size=4096`). Node's default, about 2 GB on a CI runner, ran out on kit 0.41.1 with the sites plugin installed (2.7 GB measured).
- Licence files are never translated, wherever they sit (`isLicenceFile` in `scripts/lib/rename-lib.mjs`: `LICENSE`, `LICENCE.md`, `LICENSE-*`, `COPYING`, `NOTICE`, anything under `LICENSES/`). Neither the rename nor `pnpm plugin add`/`upgrade` rewrites them, so a plugin's own licence keeps its licensor's name inside a renamed app.

## How to apply

1. Take `scripts/bootstrap.sh` and the new `scripts/lib/prereqs.sh` together; the script sources the library.
2. Take `extractSeedKey` in `scripts/lib/bootstrap-lib.mjs` and the verify wording in `stepSeed` in `scripts/bootstrap.mjs`.
3. Add `apps/web/src/ui/lib/dev-accounts.ts` and move your accounts into its `DEV_ACCOUNTS`. If you added accounts to `Login.tsx` or `seed.ts`, merge them in with a `name` and a `role`. Then take `Login.tsx`'s use of `isDevAccount` / `devAccountLabel`, and the `SEED_USERS` / `SEED_OWNER` / `GLOBAL_ADMIN` derivation at the top of `apps/web/scripts/seed.ts`.
4. Take `ROLE_LABELS` / `roleLabel` in `packages/shared/src/tenants.ts` and every `roleLabel(...)` call site in `apps/web/src/ui`. If you relabelled roles by hand anywhere, move the words into `ROLE_LABELS`. A UI test of yours that matches a lowercase role (`getByText('owner')`) now has to match `'Owner'`.
5. Take `apiKeyId` in `apps/web/src/plugins/api/auth.ts` and `apps/web/src/plugins/api/http.ts`, `apiKeyIdOf` in `apps/web/src/api/auth/api-key-session.ts`, and the `apiKeyId` option in `apps/web/tests/kit/unit.ts`.
6. Take `PluginSettingsTab` in `apps/web/src/plugins/types.ts`, its exports from `apps/web/src/plugins/api/index.ts` and `apps/web/src/plugins/api/ui-wiring.ts`, and the tab filter in `apps/web/src/ui/pages/settings/SettingsLayout.tsx` and `apps/web/src/ui/hooks/useNavigationEntries.ts`.
7. Add `apps/web/scripts/lib/seed-features.ts`. Take `hooks.seed` and `setFeature` in `apps/web/src/plugins/types.ts` and `apps/web/src/plugins/api/db.ts`, then the `runPluginSeedHooks` / `applySeedFeatures` calls and `pluginSeedContext` in `apps/web/scripts/seed.ts`.
8. Port `scripts/plugin.mjs`, `scripts/lib/plugin-lib.mjs`, `scripts/lib/plugin-lib.d.mts`, `scripts/lib/git-lib.mjs`, `scripts/lib/git-lib.d.mts` and `scripts/lib/rename-lib.mjs` (its `KIT.preserved` list) from the release; none of them holds app-specific code.
9. Copy `apps/web/tests/config/plugin-catalogue.test.ts` into the app; it runs in the `config` project against local fixture repositories and needs no network.
10. Port the text changes to `.claude/skills/rf-plugin/SKILL.md`, `.claude/skills/rf-plugin/reference.md`, `.claude/skills/rf-how-do-i/SKILL.md` §0 and `.claude/skills/rf-setup/SKILL.md`, keeping any wording the app has changed in those files.
11. Port the `SETUP.md` §1.4b and §2.7 and `docs/CONCEPTS.md` §8 and §16 text if the app still carries those sections.
12. Search the ported files for the app's own domain followed by `/plugins` and change each occurrence back to `https://rocketflare.dev/plugins`: an upgrade run before `scripts/lib/rename-lib.mjs` was ported translates that URL like any other kit domain.
13. Add `scripts/design-docs.mjs` and ten library files from the kit release: `scripts/lib/contrast`, `scripts/lib/brand`, `scripts/lib/markdown-lite`, `scripts/lib/svg-sanitize` and `scripts/lib/design-docs-lib`, each as `.mjs` and `.d.mts`.
14. Add `"design:docs": "node scripts/design-docs.mjs"` to the root `package.json` `scripts`.
15. Replace `apps/web/tests/ui/contrast.test.ts` with the kit's version, which imports its pairs from `scripts/lib/contrast.mjs`. A copy that added its own pairs to the test adds them to `contrastPairs()` in `scripts/lib/contrast.mjs` instead.
16. Add `apps/web/tests/config/design-docs.test.ts` from the kit release.
17. Copy three things from the kit release into the app, translated as usual: the `.claude/skills/rf-design/` folder (`SKILL.md`, `shape.md`, `brand.md`), the `.claude/skills/rf-start/` folder, and `scripts/detach.sh`. In an app that is already renamed, `/rf-start` only reports that every step is done.
18. Add the `rf-adapt` checklist's new row (h), "Licence", from the kit's `.claude/skills/rf-adapt/checklist.md`. `rf-adapt` is `neverPort`, so the patch does not carry it. Copy it by hand, along with the "From the design" paragraph of row (e).
19. If the app's root `LICENSE` is still the kit's MIT notice, copy it to `LICENSES/kit-MIT.txt` before changing anything, then walk checklist row (h) to write the app's own `LICENSE` and `package.json` `license` fields.
20. Add `"LICENSES/**"` to `neverPort` in `.rocketflare.json`, beside `"LICENSE"`.
21. In `apps/web/package.json`, make `typecheck` read `pnpm types && node --max-old-space-size=4096 node_modules/typescript/bin/tsc --noEmit`.
22. Take `isLicenceFile` and its use in `isExcluded` from the kit's `scripts/lib/rename-lib.mjs` (and `.d.mts`), and the `rel` argument to `materialise` in `scripts/plugin.mjs`. Then check that any plugin `LICENSE` already installed still names its licensor; a plugin installed into a renamed app before this release had its licence translated, so restore that file from the plugin's repository.

- `.claude/skills/rf-how-do-i/SKILL.md` → §0 gains a new first question above "app, or plugin?" → keep the app's own §0 text below the new question.
