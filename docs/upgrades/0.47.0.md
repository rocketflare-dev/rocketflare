## What changed

App domains let an app hold its own processes beside its plugins under one boundary check; tools gain an egress answer, plugins resolve per-plugin tags, each checkout tests on its own database, and the agent-run sweep runs hourly.

- App domains: a domain holds this app's own concepts and logic, a plugin is a reusable capability that works across domains and apps, and both are units (`docs/POSITIONING.md`, new; `docs/CONCEPTS.md` §20).
- A domain is `apps/web/src/<id>/` (`defineDomain` from `@/plugins/api`, `defineDomainUi` from `@/plugins/api/ui-wiring`), its contracts in `packages/shared/src/<id>/`, optional CLI commands in `apps/cli/src/<id>/` and tests in `apps/web/tests/<id>/`, which join the existing vitest projects.
- Five app-owned lists wire domains, one line each: `apps/web/src/app.ts`, `app-ui.ts`, `app-schema.ts`, `packages/shared/src/app.ts` and `apps/cli/src/app.ts`.
- Every registry iterates units, plugins first and then domains (`apps/web/src/units/server.ts`, `units/ui.ts`, `packages/shared/src/units.ts`), so core that read `serverPlugins` / `uiPlugins` / `sharedPlugins` now reads `serverUnits` / `uiUnits` / `sharedUnits`.
- `scripts/lib/units.mjs` is the boundary check over every unit, run by `tests/config/units.test.ts`, by `pnpm plugin check` and by `pnpm plugin add` before it copies anything.
- The unit ids `core`, `kit` and `app` are reserved; a plugin may not share a domain's id or define a table inside a domain's namespace.
- `kit:upgrade` never ports the five app lists (`skipped-app-owned`) and creates each one empty where it is missing. A new `kind: "example"` surface is reported "available, not applied" and recorded absent.
- `example-hr` (leave requests) and `example-sales` (leads) are the two example domains. They reach fresh copies only, never an upgraded one.
- `docs/CONCEPTS.md` §20 holds the recipe for adopting an app-owned plugin as a domain; `docs/ADAPTING.md` §3c now points at it, because `kit:upgrade` never ports `docs/ADAPTING.md`.
- `@testkit/integration` exports `runAgent`; `pnpm design:lint`, the guard's UI check, `knowledge-entity-types.test.ts` and the events check in `plugins.test.ts` read every unit; `/rf-how-do-i` plans an app's own process as a domain.
- Tools gain two optional fields: `egress` (can the tool send data outside the organisation: email, a webhook, a web request, a published page) and `readsContent` (it returns organisation text a model reads; absent reads as `true`).
- Every kit tool answers both. `tools/egress.ts` reads each unit's tools, and `pnpm plugin check` and `tests/config/tool-egress.test.ts` warn, never fail, for each tool without `egress`, including tools a builder returns only once connected.
- `ctx.embeddable(contentType)` also admits PNG, JPEG, GIF and WebP (`EMBEDDABLE_IMAGE_MIME_TYPES`, new in `@rocketflare/shared/files`; never SVG). `/api/files/:id` still frames PDFs only.
- The agent-run sweep (`sweepLostRuns`, `sendReminders`) runs hourly at `16 * * * *` instead of every 10 minutes, so an idle Neon compute can suspend; a lost run or a HITL reminder is now handled up to an hour late.
- Each checkout runs its tests on its own database in the shared test Postgres, `<.env.test's database>_<8 hex of its path>`, created and labelled on first use (`scripts/lib/test-db.mjs`); `pnpm eval` uses it too.
- `pnpm test:db:prune [--dry-run]` drops the test databases whose checkout no longer exists.
- `pnpm plugin` reads per-plugin release tags (`<id>-vX.Y.Z`) beside lockstep `X.Y.Z` tags and takes the newer release of each plugin; a bare version means the plugin's own tag when it exists. Pins to lockstep tags keep working.
- The kit publishes its plugin surface as `docs/plugin-surface.json`, built with `oxc-parser` (a new root devDependency) by `node scripts/plugin-api-doc.mjs`; `docs/plugin-api.md` keeps the entry list and the ledger, whose signature column is now always `-`.
- `pnpm plugin check` resolves imports in a plugin's code trees only, so an example under `docs/plugins/<id>/` no longer fails the install.
- `@testkit/unit` gains `isOwnContribution`, `ownContributions` and `expectOwnContributions`, for a plugin test that asserts only its own entries in a registry other plugins share.
- Knowledge search breaks score ties by chunk id in every retrieval leg, so equal-scored passages come back in the same order on every query.
- Every job in `ci.yml`, `deploy.yml` and `evals.yml` runs on `${{ vars.RF_RUNNER || 'ubuntu-latest' }}`, so a repository variable picks the runner; unset, nothing changes (`docs/DEPLOY.md`, "CI runners").
- `kit:upgrade`'s 3-way starting points keep the kit's own `kit` block in `launch.kit.json` and the kit's website links in `README.md`.
- `tests/ui/branding.test.tsx` no longer depends on the kit's own logo art, so a copy with its own mark passes it; `docs/upgrades/0.46.1.md` step 4 was wrong to say such a copy needs no change.
- `tool-egress.test.ts` writes its warnings to stderr, where a coding agent running the gate sees them; the UI test setup settles every React Query client before teardown, ending "window is not defined" failures.
- Kit repository only, removed by the rename: the plugin matrix (`plugin-matrix.yml`) proves every published plugin's latest release against each kit tag, and `pnpm kit:release` dispatches it against `main` and warns without blocking.

## How to apply

1. Run `pnpm kit:upgrade --apply`. It creates the five app lists (`apps/web/src/app.ts`, `app-ui.ts`, `app-schema.ts`, `packages/shared/src/app.ts`, `apps/cli/src/app.ts`) empty and ports the core that reads them. Never copy the kit's own lists, which name its examples.
2. Leave the example domains `example-hr` and `example-sales` out; the upgrade records them absent in `.rocketflare.json`. Skip migration `0038_kit-example-domains.sql`, which creates only their tables, then run `pnpm db:generate` and confirm it produces no migration.
3. If one of your plugins has the id `core`, `kit` or `app`, rename it before running `pnpm plugin check`.
4. Keep each app-owned plugin as it is unless you choose to move it: it is already a unit. To adopt one as a domain, follow the recipe in `docs/CONCEPTS.md` §20 after this upgrade (copy its trees out, `pnpm plugin remove <id> --apply --allow-dirty`, `defineDomain`, one line per app list); it needs no migration, and `pnpm db:generate` must print "No schema changes".
5. Take `apps/web/src/plugins/api/ui-wiring.ts` as it is, keeping its `biome-ignore-all` comment, or `pnpm lint:fix` moves the `defineDomainUi` export back below the others.
6. Take `docs/POSITIONING.md`, `docs/CONCEPTS.md` §16 and §20, the CLAUDE.md lines naming §20 and the `rf-how-do-i`, `rf-plugin` and `rf-design` skills as they are where you have not rewritten them; where you have, carry over the rule for where code goes. `docs/ADAPTING.md` is never ported: keep yours.
7. In your `apps/web/src/app.ts`, if its comment names `docs/ADAPTING.md` §3c, change it to `docs/CONCEPTS.md` §20.
8. Add `egress?` and `readsContent?`, with their doc comments, to the `Tool` type in `apps/web/src/api/services/ai/agent-loop.ts`.
9. Take `apps/web/src/api/services/agents/tools/egress.ts`, `apps/web/scripts/tool-egress.ts`, `apps/web/tests/config/tool-egress.test.ts` and the `egress` / `readsContent` lines on the core tools as they are.
10. Take `scripts/lib/plugin-lib.mjs`, `scripts/lib/plugin-lib.d.mts` and `scripts/plugin.mjs` as they are if you have not changed them. Otherwise add `declaredToolEgress`, `declaresToolBuilder`, `egressProblems` and `pluginCodeDirectories` to `plugin-lib.mjs`, the egress block (`readToolEgressReport`) after the tool-name check in `plugin.mjs`, and call `pluginCodeDirectories` where the unresolved-import step called `surfaceDirectories`.
11. Add `EMBEDDABLE_IMAGE_MIME_TYPES` and `isEmbeddableImageMimeType` to `packages/shared/src/files.ts`, and admit them in `embeddable` in `apps/web/src/plugins/api/http.ts` and in `makeRequestCtx` in `apps/web/tests/kit/unit.ts`.
12. **Answer `egress` for your own tools now**: every tool you appended in `buildAgentTools`, in an app-owned plugin or domain, or in an agent's own tool list. The check only warns in this release; 0.49 plans to make `egress` required, and a tool without an answer will then fail the gate. Read what each handler does: `fetch`, email, a webhook or a publish means `true`; reading or writing this organisation's own records means `false`. Ask the person "can this tool send your data outside your organisation — by email, a webhook, a web request, or by publishing a page?" and confirm the list with them once. **Answer it, never default it to `false`.** Set `readsContent: false` only on a tool that returns no organisation text.
13. Leave the `egress` warnings for a published plugin's tools: the plugin answers in its own release.
14. Move the agent-run sweep to hourly: in BOTH `apps/web/wrangler.toml` and `apps/web/wrangler.staging.toml`, replace `"*/10 * * * *"` in `[triggers] crons` with `"16 * * * *"`, and in `apps/web/src/api/scheduled.ts` change the `'*/10 * * * *'` key of `CORE_SCHEDULED_TASKS` to `'16 * * * *'`. The toml expression and the key must match, or the sweep never runs. A copy that needs faster settling or reminders may keep `*/10 * * * *` and skip this step, at the cost of keeping its Neon compute awake.
15. If an agent sets `meta.hitl.timeout` with `onTimeout: 'reject'`, keep that timeout at least an hour shorter than `AGENT_INTERRUPT_TIMEOUT`, because the hourly sweep applies it up to an hour late.
16. Take `scripts/lib/test-db.mjs`, `scripts/lib/test-db.d.mts`, `apps/web/scripts/test-db-prune.ts` and `apps/web/tests/api/test-database.test.ts` as they are.
17. In `apps/web/vitest.config.ts`, import `applyCheckoutDatabase` from `../../scripts/lib/test-db.mjs` and call `applyCheckoutDatabase(process.env)` at module level, before the config is defined.
18. Take the kit's `ensureTestDatabase()` into `apps/web/tests/helpers/db.ts`, and call `await ensureTestDatabase()` right after `safetyCheck()` in `apps/web/tests/setup.ts` and at the top of `setup()` in `apps/evals/global-setup.ts`.
19. In `apps/evals/scripts/eval.mjs`, import `applyCheckoutDatabase` from `../../../scripts/lib/test-db.mjs` and call `applyCheckoutDatabase(env)` after the loop that copies `process.env` into `env`.
20. Add `"test:db:prune": "tsx scripts/test-db-prune.ts"` to `apps/web/package.json` and `"test:db:prune": "pnpm --filter <scope>/web test:db:prune"` to the root `package.json`.
21. Take the kit's `scripts/test.mjs` and `scripts/lib/gate-changed.mjs` if you have not changed them; otherwise add the `test database:` line after the banner in `test.mjs` and `'scripts/lib/test-db.*'` to the full-run paths in `gate-changed.mjs` by hand.
22. Replace any test of your own that names `.env.test`'s database literally with one that reads `process.env.DATABASE_URL`.
23. Run `node scripts/plugin-api-doc.mjs` after porting, and commit `docs/plugin-surface.json` and `docs/plugin-api.md` as it writes them. Code of your own that read the signature column of the Markdown ledger should read the entry barrel instead.
24. Take `apps/web/src/api/services/ai/retrieval.ts` as it is if you have not changed it; otherwise add `chunks.id` as the second `orderBy` key in its four leg queries.
25. In each job of `.github/workflows/ci.yml`, `deploy.yml` and `evals.yml`, and any workflow of your own, replace `runs-on: ubuntu-latest` with `runs-on: ${{ vars.RF_RUNNER || 'ubuntu-latest' }}`. A workflow you already moved to another runner keeps working: put its label in the variable instead.
26. Optionally pick a runner with `gh variable set RF_RUNNER -b <runner label>`. Install the runner provider's GitHub app for the repository first, or the jobs queue with no runner to take them.
27. Take `scripts/upgrade.mjs` as it is. If you took a `merged/launch.kit.json` from an earlier upgrade, check that its `kit` block reads `"id": "rocketflare"` and `"name": "Rocketflare"`, and put them back if it names your app.
28. Take `apps/web/tests/ui/branding.test.tsx` as it is. If your `LogoMark.tsx` is still your own inline mark, wrap it as the kit's does: read `logoUrl` from `useAppInfo()`, render `<img data-brand-logo … onError>` when it is set, and your mark as `BundledMark` otherwise.
29. Take `apps/web/tests/ui/helpers/renderWithProviders.tsx` and `apps/web/tests/ui/setup.ts` as they are if you have not changed them; otherwise add the client tracking set and `settleTestQueryClients()` to the helper and call it after `cleanup()` in the setup's `afterEach`.
30. Optional: in an app plugin's or domain's tests, replace an exact assertion over a registry other units share (a provider, tool or nav list) with `expectOwnContributions('<id>', items, ['<id>:…'])` from `@testkit/unit`.
31. Per-plugin tags need nothing from you: a plugin installed at a lockstep tag upgrades to its own `<id>-vX.Y.Z` release with `pnpm plugin upgrade <id>` once it has one.

## Conflicts to expect

- Core files that loop over `serverPlugins` / `uiPlugins` / `sharedPlugins` → now `serverUnits` / `uiUnits` / `sharedUnits` → keep your local line and take the new name.
- `apps/web/src/api/services/agents/tools/*.ts`, if you edited a core tool → two new lines after `schema` → keep your change and add `egress` and `readsContent`.
- `[triggers] crons` in both tomls, if you added crons of your own → only the `*/10` line changes → keep yours and swap that one line.
- `docs/plugin-api.md` → regenerated in a new, shorter shape → take the kit's version, then run `node scripts/plugin-api-doc.mjs`.
- A workflow already moved to another runner → `runs-on` now reads `RF_RUNNER` → keep your label as the variable's value.
