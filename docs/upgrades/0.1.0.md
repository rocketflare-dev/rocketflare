## What changed

The first release: the whole kit — `docs/CONCEPTS.md` §§1–12 — and the §13 upgrade path that lets a
detached, renamed copy absorb every release after it.

- Tenancy, auth, the API shell, and the database with its inert RLS — `docs/CONCEPTS.md` §§1–4.
- Jobs and realtime, email and storage, the UI shell — §§5–7.
- Analytics, the AI layer, deployment, the CLI, the shared contracts — §§8–12.
- The upgrade path (§13) — `.rocketflare.json` records the release a copy came from, the names it
  was renamed to and the surfaces meant to be replaced; `scripts/upgrade.mjs` fetches the kit into a
  throwaway mirror, translates its diff into the copy's own names and drops everything belonging to
  a part the copy deleted. `/rf-upgrade` drives it, guided by notes like this one.

## How to apply

1. Nothing to apply. This is the release every other note chains back to, and the version a copy
   made from the kit at 0.1.0 carries in `.rocketflare.json`.
2. In a copy made *before* 0.1.0 was tagged, adopt the baseline once: `node scripts/upgrade.mjs
   --adopt 0.1.0`.

## Conflicts to expect

None.

## Verify

1. `pnpm lint && pnpm typecheck && pnpm test && pnpm build` is green.
2. `pnpm kit:upgrade` in a copy reports "Already on 0.1.0".
