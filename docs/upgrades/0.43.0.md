## What changed

`pnpm gate --changed` gates only what a branch changed, the full gate is faster (TypeScript 7, shared test registries), and a copy no longer runs the kit's tooling tests.

- `pnpm gate --changed[=<ref>]` runs lint on the changed files and typecheck, test and build only where the change reaches (`scripts/lib/gate-changed.mjs`, `docs/CONCEPTS.md` §4). A config, lockfile, migration or harness change runs the full gate. For local commits: the full `pnpm gate` still runs before a push and in CI.
- `pnpm plugin` runs the host's Biome directly instead of through `pnpm exec`.

- The tests of `scripts/**` and the rf-security runner moved from `apps/web/tests/config/` to `apps/web/tests/kit-only/` (rationale: `docs/CONCEPTS.md` §13, "Kit-only files").
- The toml snapshots moved with `patch-toml.test.ts`, from `apps/web/tests/config/fixtures/` to `apps/web/tests/kit-only/fixtures/`.
- `scripts/plugin.mjs` runs `node_modules/.bin/biome`, and skips formatting with a warning when the host has none.
- `tsc` is TypeScript 7.0.2, the native compiler: the web typecheck drops from ~14 s to ~3 s and needs no 4 GB heap; code that parses TypeScript imports `typescript6` (`npm:typescript@6.0.3`). `apps/evals/css-modules.d.ts` declares `*.css`, because TypeScript 7 checks side-effect imports and a plugin UI the eval kit compiles may import a stylesheet.
- The `ui` and `config` tests share one module registry per worker, as `api` does. A file that mocks a module or a global runs in the new `ui-isolated` or `config-isolated` project, chosen by the same heuristic as the api marker, so no file needs marking. The kit's ui tests drop from ~21 s to ~8 s. Every shared project sets `isolate: false` in `vitest.config.ts`, and the api and ui setups undo `vi.stubGlobal` after each file.
- `pnpm test <suite…> [file…]` (`api`, `ui`, `config`, `driver`) runs one suite, its shared and isolated projects together. The `apps/web` `test:*` scripts are one-line aliases for it, `test:shared` and `test:isolated` are gone, and no `package.json` names a vitest project any more.
- The local test worker limit rises from 6 to 10 on machines with the cores for it.
- More of the kit's tests leave a copy's gate: `ci-workflows` (the kit's workflow shape and its release-check script), the `plugin check` MCP fixtures, the 0027 migration backfill, and the pins on the kit's exact entity types and job types (`kit-makeup`). Eleven `api` files that open no database run in `config`, now guarded against outbound network like `api`.
- Tests no longer break when an app renames itself or removes chat or documents: the "never the kit's name" checks spell the name so the rename cannot rewrite it (`tests/helpers/kit-name.ts`), and the navigation test pins no removable page.
- `overrideResolveChatForTests` (`@/api/services/ai/resolve`) lets a test hand the code a fake chat client without `vi.mock`, so its file shares the `api` registry; `tests/api-setup.ts` resets it after each file. `chat.test.ts` uses it.
- A test that only spies on or stubs a global no longer needs `// @vitest-isolate`: Vitest restores spies after each file, and the api, ui and config setups now undo `vi.stubGlobal` and `vi.stubEnv`. The heuristic flags only `vi.mock`, `vi.doMock` and `vi.resetModules`, twelve kit api files dropped the marker, and the isolation contract also checks every installed plugin's `tests/api`.
- `overrideResolveDecisionsForTests` (`@/api/services/ai/resolve`) is the decisions twin of the chat override, reset by `tests/api-setup.ts` too; seven more api files (`agent-research`, `agent-replay`, `agent-run-workflow`, `agent-triage-research`, `agui-run`, `chat-compaction`, `chat-tools`) use the overrides instead of `vi.mock` and share the registry.
- `overrideKnowledgeEntityTypesForTests` (`@/api/services/knowledge/registry`) lets a test register fixture entity types without `vi.mock`, reset by `tests/api-setup.ts`; `knowledge-extract`, `knowledge-promote`, `security/knowledge-extract-long-values` and `security/knowledge-visibility-producer` use it and share the registry.
- `withServerPlugins` (`tests/helpers/server-plugins.ts`) splices fixture server plugins into the real barrel for one file instead of `vi.mock('@/plugins/server')`, for code that reads the barrel at call time; `plugin-tools`, `mcp-plugin-tools`, `plugin-tenant-status-hook` and `security/chat-approval-gates` use it and share the registry.
- A new `api-fixtures` project shares one registry per worker with the fixture agents installed in the real plugin barrels before the app loads (`tests/api-fixtures-setup.ts`); an api file opts in with `// @vitest-fixture-agents` on line 1 instead of mocking both barrels. Eighteen kit files moved there, and `pnpm test api` runs it.
- The core agent route and runtime tests left the `summarize-text` example's files for `agent-run-routes.test.ts` and `agent-run-runtime.test.ts`, on the fixture agent, so an app deleting the example keeps them; `security/plugin-member-checks` uses a fixture plugin, not `example-feature`.
- The UI bundle's chunk checks run after `vite build` (`scripts/check-ui-bundle.mjs`, called by `build:ui`), so they always read the build just made; in the gate they used to skip, because the tests ran before the build.

## Conflicts to expect

- `apps/web/tests/config/<file>.test.ts` → moved to the kit-only project, which a copy does not carry → delete your copy unless you changed it.
- `apps/web/tsconfig.json` → `baseUrl` removed and `paths` made `./`-relative → keep your own extra `paths` entries, each `./`-prefixed.
- `apps/web/package.json` `test*` scripts → the kit's are now one-line `test.mjs` aliases → take the kit's, and move any project or flag of your own into `SUITES` in `scripts/lib/test-plan.mjs`.
- `apps/web/tests/ui/setup.ts` → keep your own setup lines and add the resets.
- `apps/web/tests/api/agent-runs.test.ts`, `agent-run-workflow.test.ts` → cut down to the example's own checks → take the kit's, and move a test of yours that is not about `summarize-text` into `agent-run-routes` or `agent-run-runtime` on `FIXTURE_AGENT`.
