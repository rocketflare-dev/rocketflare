## What changed

The knowledge base becomes measurable and structure-aware: eval corpora, structured chunks, model-consistent search with re-embedding, dedupe, retry, a reranker seam, metered spend, and typed knowledge facts extracted from documents behind a `knowledge-facts` flag.

- Eval corpora: a directory under `apps/evals/datasets/` with `docs/*.md` and answer keys (`retrieval.jsonl`, `chat.jsonl`, `entities.jsonl`, `facts.jsonl`, `conflicts.jsonl`), ingested once with a real embedder (`docs/EVALS.md` § Corpora).
- New suite `knowledge · retrieval` and judges `RecallAtK(k)`, `MRR()`, `ContextPrecision(k)`; `chatHarness({ corpus })` runs a corpus's `chat.jsonl` inside `chat · knowledge`.
- New scorers `factExtractionScore` and `conflictDetectionScore` in `apps/evals/kit/scoring.ts`; the run summary prints a mean row per suite.
- `GEMINI_API_KEY` alone is now enough for corpus suites: it is used as a tenant embeddings row on `gemini-embedding-001`.
- Chunks are exact slices of the stored text (`chunks.char_start`/`char_end`; overlap by starting the next window earlier); `charOffset` reads the stored offset.
- Every chunk begins and ends at a markdown heading: whole sections that fit a window are packed together, a longer one is cut inside; each chunk stores the headings its sections share as `heading_path` (`Pricing › Annual plans`), prefixed to the EMBEDDED text only.
- GFM tables (spreadsheet sheets from `toMarkdown`) split only between rows; a chunk holding rows without the header stores it as `table_header`, also embedded and indexed.
- Lexical search reads a generated `chunks.search_vector` (heading path + table header + text, GIN) instead of computing `to_tsvector` per query.
- Every dense leg filters on `chunks.embedding_model` = the query vector's model; another model's chunks are found by keyword only.
- `documents.content_hash` (sha-256 of the normalised text): an unchanged `externalId` upsert is `mode: 'unchanged'` (no chunking or embedding; metadata and grants still update).
- A plain ingest or text upload matching a tenant-wide document of the same source answers it: `200` with `deduplicated: true` (`ingestDocumentResponseSchema`); `PluginIngestResult` gains `deduplicated`.
- `GET /api/ai/documents/health` (admin+, `documentsHealthSchema`): documents by status, today's `embeddingModel`, `staleEmbeddings` (indexed documents with a chunk from another model) and `staleChunks`.
- New job `document.reembed` (`{ tenantId, model }`): ≤ 20 documents / 400 chunks per message, re-enqueued while more remain; old chunks stay searchable on a failure. `POST /api/ai/documents/reembed` (admin+) answers `202`.
- Saving or deleting an `embeddings` config that changes the resolved model enqueues `document.reembed` after the commit; without `JOBS_QUEUE` the save still succeeds and logs a warning.
- `POST /api/ai/documents/:id/retry` (owner or admin+): `202` with the row `pending` and `job` (`document.convert` when there is no text, else `document.index`); `409 document_not_failed`. The Documents page shows Retry on a failed row (errors toast, success does not).
- The jobs consumer dead-letters into `<app>-jobs-dlq` / `<app>-jobs-dlq-staging` (`dead_letter_queue`), created by `pnpm provision cloudflare`; no consumer is bound to it.
- Inline indexing is an `ingest document` span (under the active span, else a root on the request tracer) with its embeddings batches as children; `IngestDeps.tracer` is new.
- `indexDocument` takes `markFailedOnError: false`; `markDocumentFailed` and `resolveEmbeddingsModel` (the resolved model, no client) are exported.
- Reranking (`services/ai/rerank.ts`, the `RerankFn` seam): search reranks the top 50 fused candidates, then cuts to `limit`; hits gain `rerankScore` (0–1, null when nothing reranked) and `rank` is the final order. `searchKnowledgeChunks` answers `rerank` (applied, model, latency or the skip reason) and takes `rerank: false` and `defer`.
- New AI scope `rerank` (`AI_SCOPES`, `aiReadinessSchema.rerank`): a tenant row is `openai_compatible` (a Cohere-style `POST {base}/rerank`; dialect from the host — Cohere, Voyage, Fireworks presets) or `workers_ai`; with neither, Workers AI `@cf/baai/bge-reranker-base` when `[ai]` is bound, else no reranking. Settings → AI shows a Rerankers section and tests a row by reranking two documents.
- `RERANK_MIN_SCORE` (optional `[vars]`, 0–1, unset = off) drops reranked hits below it.
- Knowledge metering: document, re-embed and query embeddings and every rerank call write `ai_usage` rows `knowledge.embeddings` / `knowledge.rerank` (`KNOWLEDGE_USAGE_FEATURES`; extraction writes `knowledge.extraction`), with the provider's token count or a character estimate; a ledger failure never fails an ingest or a search. `EmbeddingsClient.embedWithUsage` is new and optional. `bge-reranker-base` is priced.
- `KNOWLEDGE_TENANT_DAILY_COST_USD` (optional `[vars]`, unset = no cap) and `knowledgeSpendToday` / `knowledgeExtractionAllowed` in `services/ai/usage.ts`: only extraction pauses at the cap; indexing and search never do.
- `pnpm eval … --rerank none|fireworks` measures retrieval with a reranker; the summary prints the median rerank latency.
- Knowledge facts (D43, `docs/CONCEPTS.md` §9): new contracts `@rocketflare/shared/ai/knowledge-facts` (entity type declaration, `FACT_STATES`, `SOURCE_TRUST` + `trustRank`, fact, entity card, review action, possible match, `factHitSchema`) and tables `knowledge_entities` (staging entities, trigram index on `name`) and `knowledge_facts` (`document_id` cascades, `chunk_id` set null). Nothing writes them yet.
- `scripts/migrate.ts` creates `pg_trgm` beside `vector`; migration 0028 creates it too.
- Entity type registry: `EntityTypeRegistration` and `defaultEntityResolver` (trigram over `labelColumn`/`aliasColumns`, tenant-filtered) in `@/plugins/api`; `APP_ENTITY_TYPES` in `apps/web/src/api/services/knowledge/entity-types.ts` (app-owned, empty); `knowledgeEntityTypes()` composes and validates (plugin types `<id>.<name>`, app types without a dot, snake_case keys, JSON-schema-renderable facts, no duplicates).
- New plugin field `ServerPlugin.knowledgeEntityTypes` (a field, not a barrel); `example-feature` registers `example-feature.note` over `example_notes`.
- Fact extraction: new job `knowledge.extract` (`{ tenantId, documentId, contentHash? }`), enqueued by `afterTextIndexed` only when a document's text changed, the tenant has the new core flag `knowledge-facts` (default off) and an entity type is registered. One `submit_facts` call per heading-bounded section, prompt key `knowledge-extract` (assignable in Settings → agent models).
- Each candidate survives only if its quote is verbatim in the chunk, its value parses against the key's zod schema, and every date resolves in code against the document's date; it is then resolved to a domain row, a staging entity (trigram ≥ 0.6, else a possible match from 0.45 or embedding cosine 0.9) or a new staging entity. A section's candidates are checked together: two values for one entity and key over the same validity drop as `ambiguous`, and a placeholder value (`<UNKNOWN>`, `N/A`) is no value.
- Fact state: `accepted` (or `unconfirmed` below 0.7 confidence), corroboration confirms, a different value marks both `conflicting`, disjoint explicit validity windows supersede the earlier one; nothing writes a domain column. Re-extraction replaces a document's facts.
- `isPreferredOver` / `preferredFact` (shared): of disagreeing facts an answer leads with the newer one when it is at least as trusted, else the older — derived, never stored.
- `documents.origin` (`upload` | `integration`) and `documents.reviewer_user_id`; `@/plugins/api` `ingestDocument` / `ingestDocumentFile` set `origin: 'integration'` and take an optional `reviewerUserId`. `document.index` gains `skipExtraction`.
- At `KNOWLEDGE_TENANT_DAILY_COST_USD` the extraction job re-enqueues itself for the next UTC day (≤ 12 h a hop).
- New eval suite `knowledge · facts` (`pnpm eval facts`, `apps/evals/kit/facts.ts`): extracts a corpus in date order through the job body and scores precision, recall, conflicts caught, false alarms and winner accuracy.
- Eval corpora may carry `corpus.json` `{ "organisation" }` (the business the knowledge base belongs to); the eval kit's `normalizeName` now drops a trailing legal form (`Ltd`, `Limited`, `LLP`, `PLC`, `Co`, `Inc`).
- Knowledge facts review API `/api/knowledge` (behind the `knowledge-facts` flag, 404 when off): `GET /review`, `POST /facts/:id/review { action: confirm|reject|prefer }`, `GET /entities/:type/:id`, `POST /entities/:id/merge|promote|keep-separate`; new CASL subject `KnowledgeFact` (member read + update, admin+ manage) and five error codes.
- A fact inherits its document's visibility: hidden facts are a 404, and a conflict with a hidden fact is invisible to that reader. `prefer` rejects the other sides (never supersedes); merge and promote re-decide shared keys.
- Chat and agent tools: `lookup_facts` and a `facts` block on `search_knowledge`, only for a tenant with the flag; `AgentToolContext.features` is new, and the chat prompt and both tool descriptions require citing every side of a conflict.
- New eval suite `chat · conflicts` (`pnpm eval conflicts`): one chat turn per planted conflict, with facts extracted first; `chatHarness` takes `prepare`.
- Knowledge facts keep a person's decision across re-extraction: a re-read fact with the same entity, key and value reuses the confirmed or rejected row (new citation, same decision); a decided fact the new text no longer states is deleted unless a section failed. `ExtractionReport.decisionsKept` is new.
- Every review action and every extraction run that wrote or removed facts nudges `entity.changed { entity: 'knowledge' }` after commit; `access.changed` also invalidates `['knowledge']`.
- Review API: a fact review item carries `entity { kind, type, id, name }`; the entity card's `entity` carries `promotable` and `reviewerUserId`; a possible match with no candidate the reader can see is no longer counted in `pagination.total`.
- Knowledge facts UI behind the `knowledge-facts` flag: the entity page `/knowledge/entities/:type/:id`, inline "Is this still right?" (Confirm / Not right / Use this one), a "To review" view on the Knowledge page (`/documents?view=review`), a count badge on its nav item, and an entity card in chat (`CUSTOM kit.entity`, `chatEntityCardSchema`).
- Stored document text has CRLF normalised to LF; search hits (and `searchKnowledge` hits) gain `headingPath` and `page` (always null: `toMarkdown` emits no page markers).
