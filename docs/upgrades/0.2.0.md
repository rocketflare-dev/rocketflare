## What changed

**Breaking, with three migrations.** Groups and per-row visibility for documents and dashboards,
AG-UI as the wire protocol for chat and agent runs, a chat inspector with per-turn model
attribution, a document viewer, and `run_worker_first` covering every API prefix.

- **Groups and per-row visibility — migration, breaking** (D29, `docs/CONCEPTS.md` §1). Five new
  tables and a `visibility` column (`tenant | groups`, default `tenant`) on `documents` and
  `analytics_pages`. Existing rows are all `tenant`, so an app with no group types is unchanged.
- **Visibility is the column, not the absence of grant rows.** Deleting the last group a document
  was shared with leaves an empty grant list, which matches nobody, so the row narrows to its owner
  and admins instead of publishing. Deleting a group still granting anything is 409 `group_in_use`;
  `?force=1` narrows.
- **`services/access.ts` is the only place row visibility is expressed, and three signatures change
  — breaking.** `searchChunks`, the three `document-content.ts` readers and `AgentToolContext` all
  take an `AccessScope` where they took a `tenantId`. The predicate is ANDed with the tenant one,
  never replacing it; `bypass` is `isAdminLevel`.
- **Every read path took the scope**, and a row you may not see answers the SAME 404 as a missing
  one. An agent run builds its scope at EXECUTE time from `requestedByUserId`. Two traps:
  `searchChunks` sets `hnsw.iterative_scan = relaxed_order` `LOCAL` only when a predicate is in
  play, or an approximate HNSW scan returns an empty dense half; and raw predicate SQL cannot go
  into `db.query.X.findFirst`, which renames its table.
- **New surfaces** `/api/groups`, `PUT /api/members/:userId/groups` and a `visibility` PUT per
  resource; membership grants **read only**. New CASL subject `Group`; new realtime event
  `access.changed`. Contracts gained `visibility` and `groups[]` on documents and analytics pages,
  `groups[]` on `memberSchema`, and optional `visibility` / `groupIds` on the ingest schemas — a
  member may name only their own groups (403 `group_not_yours`).
- **AG-UI is the wire protocol for chat and agent runs — breaking** (D28, `docs/CONCEPTS.md` §9).
  `kitAguiEventSchema` and the `kit.` CUSTOM namespace replace the old chat stream, and frames carry
  **no `event:` line**. `packages/shared` gains a third dependency, `@ag-ui/core`, **pinned
  exactly** because its schemas ARE the wire format.
- **A long chat forgets deliberately — migration and a new `[vars]` key.** `CHAT_HISTORY_MAX_CHARS`
  (24 000) bounds a turn's history instead of a message count, which is not a limit at all.
  `conversations` gains nullable `summary` and `summarised_through_id`, folded in by a new
  `chat.compact` job. New prompt key `chat-compaction`; new notices `history_truncated` /
  `history_summarised`.
- **Chat calls the knowledge tools by default**, capped by `CHAT_MAX_TOOL_TURNS` (6).
  `CHAT_KNOWLEDGE_TOOLS = "false"` restores the old, cheaper, always-token-streaming behaviour. The
  `chat` prompt gained guidance on when NOT to call them; without it a small model summarises a
  random document in reply to "Hello".
- **New surface `POST /api/agui/run`**, the AG-UI `RunAgentInput` endpoint: the server is the
  transcript and the client supplies only the tail, so an unknown `threadId` is adopted, the last
  message is the new turn, a replayed UUID is not re-inserted, and a non-empty `tools[]` is refused
  with 400. **`GET /api/agents/runs/:id/agui`** projects `agent_run_events` at read time.
- **The Workers AI zero-key floor is `@cf/zai-org/glm-4.7-flash`** (was Llama 3.3 70B): it accepts
  `tool_choice`, streams tool calls and text, and is cheaper. A tenant that pinned a model is
  unaffected. `readWorkersAiPart` now reads BOTH answer shapes, without which newer models look like
  they answered with nothing.
- **`ToolCallAssembler` concatenates streamed tool-call fragments by `index`**, without which each
  fragment becomes one broken `tool_use` — **take this if you added models to the streaming list**.
  `WORKERS_AI_TOOL_CHOICE_MODELS` is the eleven models declaring `tool_choice`, serving the picker,
  `workersAiSupportsToolChoice` and `workersAiStreamsTools`; the picker drops three, but a stored
  config naming one keeps working and stays priced. `recoverForcedToolCall` also strips a
  `{"type":"function",…}` envelope when the object names the tool.
- **A chat inspector, and the per-turn model it needs — migration.**
  `conversations.provider`/`model` were frozen at creation and quietly wrong; both refresh every
  turn now, and `messages` gains nullable `provider` / `model` (existing rows keep NULL and read as
  "unknown"). New `GET /:id/stats` (admin+ `manage AiConfig` on top of ownership) and `POST
  /:id/compact`, which adds an optional `force` to the `chat.compact` payload.
- **A document viewer, and three read endpoints behind it.** `GET
  /api/ai/documents/:id/{content,passages,card}`, all `read Document`, all tenant-predicated,
  unknown and other-tenant ids answering the SAME 404. `/content` is one window (default 20 000, cap
  50 000); a document with no text is a **409**, never an empty window. `document-content.ts` is now
  the one implementation and `get_document` delegates to it, with **its JSON unchanged down to key
  order**.
- **Inline PDFs need two things and the second is the blocker.** `INLINE_MIME_TYPES` adds
  `application/pdf`; everything else still downloads. But `securityHeaders` stamps `X-Frame-Options:
  DENY`, which forbids framing by ANY origin including our own, so a route that has PROVED the
  content type sets `c.set('embeddable', true)` for that ONE response.
- **`kit.document` joins the `kit.` CUSTOM namespace**, emitted by the chat stream after the
  `TOOL_CALL_RESULT` it came from and by the agent-run projection through the same pure mapper.
  Nothing about a card is stored. `typeLabel`, `contentType` and `sizeBytes` become **nullable**;
  `ChatBubble` gains `documents`.
- **`[assets] run_worker_first` now lists every prefix the Worker owns, in both tomls — breaking.**
  Cloudflare's asset router runs BEFORE the Worker and answers anything it treats as a NAVIGATION
  with `index.html` — and an `<object>` embed and an `<a download>` click are navigations. No test
  could catch it, since every API test drives the Hono app directly. **Take it even if you skip the
  viewer.**
- **`get_document`'s window is capped by the CALLER** — 50 000 for an agent run, 6 000 for chat,
  clamped rather than rejected. **Cached input tokens were billed twice outside Anthropic**, because
  OpenAI's `prompt_tokens` includes `cached_tokens`; `fromOpenAiUsage` subtracts it and existing
  rows keep their frozen cost. CI now also runs on pull requests, where the porting-note guard could
  previously run only after merge.
- **`deploy.yml` asks whether there is anything to deploy**, through a `guard` job gating both
  deploy jobs — an app always deploys, and only the kit, carrying `<PLACEHOLDER>` ids, is skipped.
  `parseNote` now reads a block-sequence `migrations` list as well as an inline one, and
  `scripts/release.mjs` patches `kit.version` in place rather than through `JSON.stringify`.
- **UI.** Settings → Groups, a Groups column and Edit groups dialog on People, `AccessPicker` /
  `AccessBadge` / `VisibilityModal` (markdown-free, so they stay in the eager barrel), a Visibility
  action on Knowledge rows and the dashboard header, and an empty selection warned about rather than
  blocked. The viewer is lazy with `?offset=` / `?chunk=` / `?q=` deep links; a chat tool call is
  one row; Settings → AI keys model suggestions BY SCOPE.

## How to apply

1. Add `[assets] run_worker_first`, listing every prefix the Worker owns, to BOTH
   `apps/web/wrangler.toml` and `apps/web/wrangler.staging.toml`, and take
   `apps/web/src/api/utils/routes/api-prefixes.ts`. Do this first even if you take nothing else.
2. Add `CHAT_HISTORY_MAX_CHARS = "24000"` and `CHAT_KNOWLEDGE_TOOLS = "true"` to `[vars]` in BOTH
   tomls, choosing `"false"` to keep chat tool-free. A `[vars]` key in one toml only fails
   `apps/web/tests/config/wrangler-parity.test.ts`.
3. Install the AG-UI dependencies and **pin all four exactly**: `@ag-ui/core` in `packages/shared`,
   and `@ag-ui/core`, `@ag-ui/encoder`, `@ag-ui/proto` in `apps/web`.
4. Port the groups contracts and schema: `packages/shared/src/groups.ts`, the three schemas that
   gained fields, `apps/web/src/db/schema/{groups,document-groups,analytics-page-groups}.ts`, and
   the `visibility` columns in `_helpers.ts`, `documents.ts` and `analytics-pages.ts`. Keep
   `group_members`' composite primary key `(group_id, user_id)` and its composite foreign key
   `(tenant_id, user_id) → tenant_users` with cascade, so losing an organisation membership drops
   the group memberships in the database.
5. Port the other two schema changes: nullable `summary` and `summarised_through_id` on
   `conversations`, and nullable `provider` and `model` on `messages`.
6. Run `pnpm db:generate`, read the emitted SQL, then `pnpm db:migrate`. **Never copy the kit's
   migration files** — a `meta/*_snapshot.json` describes a whole cumulative schema, and the kit's
   has never heard of an adopter's tables.
7. Port `apps/web/src/api/services/{access,groups}.ts`, `routes/groups.ts` and its mount, then the
   auth context: the third LATERAL join in `auth/sessions.ts`, the Bearer path in
   `middleware/auth.ts`, and `api/types.ts`.
8. Point every read path at the new scope argument — the documents routes, `POST /search`, `GET
   /api/files/:id`, the knowledge and chat tools, and the analytics pages routes. A copy that
   deleted the knowledge or analytics feature takes only the half it still has and deletes the
   matching describe blocks in `apps/web/tests/api/access-visibility.test.ts`.
9. Add the `Group` subject to `CORE_SUBJECTS`, to `apps/web/src/permissions/abilities.ts` and to
   `apps/web/tests/config/permissions.test.ts`, and add `access.changed` with its four invalidation
   roots to `packages/shared/src/realtime.ts`.
10. Decide whether a tenant API key should carry its creator's groups. It does by default, re-read
    every request. To give keys tenant-visible content only, change `resolveBearerAuth` in
    `apps/web/src/api/middleware/auth.ts` — one line, and a policy choice.
11. Take the protocol files: `packages/shared/src/ai/agui.ts`,
    `apps/web/src/api/services/ai/{agui,chat-turn}.ts`, `routes/{chat,agui}.ts`,
    `services/agents/agui-projection.ts`, `apps/web/src/ui/lib/{sse,aguiStream}.ts` and
    `hooks/useChat.ts`.
12. Re-map any code of your own that read the chat stream: `message.start` → `CUSTOM kit.chat.ids`;
    `text.delta` → `TEXT_MESSAGE_CONTENT`, **one text message per model turn, so accumulate across
    `messageId`s**; `tool.start` → `TOOL_CALL_START`/`ARGS`/`END`; `tool.end` → `TOOL_CALL_RESULT`;
    `usage` → `CUSTOM kit.usage`; `message.end` → `RUN_FINISHED`; `error` → `RUN_ERROR`; and a
    cancelled run closes with **no terminal event**, which IS the cancellation signal. A variant a
    copy added to `chatStreamEventSchema` becomes a CUSTOM event under that copy's OWN prefix, never
    `kit.`.
13. Take `apps/web/src/api/services/ai/providers.ts`, `services/ai/client.ts` and
    `packages/shared/src/ai/pricing.ts` wholesale if the kit's provider catalog is unmodified. If
    you added models to the picker, merge by hand and check each against `pnpm --filter
    @rocketflare/web exec wrangler ai models schema <model>`.
14. Take the document viewer, which needs no migration: `packages/shared/src/ai/embeddings.ts`,
    `packages/shared/src/files.ts`, `apps/web/src/api/services/ai/document-content.ts`,
    `routes/ai-documents.ts`, `services/agents/tools/get-document.ts` (now a delegation) and
    `services/ai/retrieval.ts`, which exports `chunkCharOffsetSql`. Add `document-content.ts` and
    the viewer page to the `feature-knowledge` surface's paths in `.rocketflare.json`.
15. Merge the framing half by hand rather than overwriting:
    `apps/web/src/api/middleware/security-headers.ts`, `routes/files.ts` and `api/types.ts`. Set the
    `embeddable` flag **before** the `If-None-Match` 304 early return, or the embed works once and
    goes blank on the revalidation an `<object>` sends.
16. Read the `.github/workflows/**` diff before taking it — those paths are `manual`. Port the
    `guard` job and the two `if:` conditions in `deploy.yml` by hand into an edited workflow.

## Conflicts to expect

- `services/ai/retrieval.ts`, `document-content.ts`, any `AgentToolContext` builder → all take an
  `AccessScope` rather than a `tenantId` → change the call site, using `fullAccessScope(tenantId)`
  only where a maintenance path should genuinely see everything.
- A custom `toDocument` or `toAnalyticsPageDto` → both take a second `groups` argument → pass it. A
  member-list endpoint of your own → `memberSchema` carries `groups[]` → resolve groups in the same
  query.
- Any raw SQL predicate spliced into a `db.query.*` relational query → that query renames the table
  it selects from → rewrite it as `db.select()`. In the EXISTS subquery itself, name the table with
  a LITERAL alias: a drizzle column object renders with whichever alias is in scope where the
  fragment lands, so the wrong one compiles and returns wrong rows (`.claude/rules/api.md`).
- `apps/web/src/ui/lib/chatStream.ts` → deleted, and `sendChatMessage` is now `runChatTurn` in
  `lib/aguiStream.ts` → re-point the import.
- A `readSse` call site → it takes a `parse` argument now → pass `kitAguiEventSchema.safeParse`. A
  test using `sseFrames` / `sseResponse` → replaced by `aguiFrames` and `aguiRun`, and anything
  keying on the SSE `event:` field must read `JSON.parse(data).type`.
- `middleware/security-headers.ts` → built from a shared `CSP_BASE` with two `frame-ancestors`
  variants → move an added directive into the base, or it applies to only one.
- A link of your own to `/search?documentId=` → Search's hit title is a `<Link>` into the viewer now
  → re-point it.
- `permissions/abilities.ts`, a custom `components/shared/index.ts` barrel, a customised
  `get-document.ts` and `.github/workflows/deploy.yml` → all gain new entries or arms → merge by
  hand.
- Bundle: on the kit `gzip -c apps/web/dist/api/worker.js | wc -c` went from 1 311 621 to 1 336 048,
  about 24 KB gzip. Measure your own if you are near the free plan's 3 MiB limit.

## Verify

1. `pnpm lint && pnpm typecheck && pnpm test && pnpm build` exits 0.
2. `pnpm web test:config` is green (`agui-contract`, `shared-imports`, `ui-bundle`,
   `document-helpers`, `permissions`, `upgrade-lib`), `pnpm web test:api` is green (`groups`,
   `access-visibility`), and `node scripts/release-check.mjs --deployable` reports `deployable=true`
   in an app.
3. With `pnpm dev` and `pnpm seed --demo`, as `member@example.test` the seeded Finance-only document
   and "Finance review" dashboard are absent from Knowledge, Search, Analytics and the chat box's
   answers; as `owner@example.test` all of them are there.
4. With both browsers open, move `member@example.test` into Finance under Settings → Groups and
   watch the content appear without a reload — that is `access.changed` working.
5. Upload a PDF on `/documents` and open it from the Knowledge list: it **renders in the page**,
   which proves the framing fix where the disposition alone does not. Then `curl -sI` a stored PDF
   for `inline` + `SAMEORIGIN`, an uploaded `.html` for `attachment` + `DENY`, and any JSON route
   for `DENY`.
6. Send a chat message and confirm devtools shows `data:`-only frames carrying `RUN_STARTED → CUSTOM
   → TEXT_MESSAGE_* → RUN_FINISHED`; press Stop mid-stream for no error toast and no terminal frame.
