## What changed

`kit:upgrade` runs the target release's upgrader and 3-way merges stale patches, `pnpm test` reads its ports from the compose file, plugin upgrades stop duplicating core edits, and plugins gain Home cards, framing and larger upload caps.

- `pnpm kit:upgrade` hands the run to the TARGET release's `scripts/upgrade.mjs` (extracted with `scripts/lib/` into `.upgrade/tool/<v>/`) when it differs from the copy's, so upgrader fixes inside the range apply to the jump that crosses them (#178).
- A file whose patch no longer applies is merged 3-way (`git merge-file`, base = the old kit file, theirs = the new one, both translated); a clean merge is applied and staged, a conflict is a `*.rej` or, with the new `--3way`, conflict markers; `--continue` refuses while a marker remains. A `manual` file the kit changed gets the merge as a starting point under `.upgrade/work/<v>/merged/`.
- `scripts/lib/rename-lib.{mjs,d.mts}` is always ported verbatim (`ALWAYS_PORTED_TOOLING` in `upgrade-lib.mjs`), whatever a copy's `neverPort` says: `plugin.mjs` imports `isLicenceFile` from it, and a copy left on the old file crashed its first `pnpm plugin upgrade`. The kit's `neverPort` no longer lists it.
- `pnpm test` reads the test Postgres and Neon proxy ports from `apps/web/docker-compose.test.yml` (`testPorts` in `scripts/lib/test-plan.mjs`), reuses another checkout's servers only on those ports, and refuses a `.env.test` that connects elsewhere; the security sandbox's Postgres listens on the port `.env.test` connects to (`SECURITY_PG_PORT`).
- `pnpm plugin add|upgrade|remove` match a core-edit line as code (`findEditLine`), so a line Biome wrapped is not written again (the duplicate `@nivo/heatmap` key) and is reverted whole; `plugin upgrade` removes from `run_worker_first` the API prefixes the release dropped (`pruneWorkerFirst`; one entry of a kit-owned path such as `/mcp` stays).
- `createExecutionContext()` in `apps/web/tests/mocks/bindings.ts` implements `mapVirtualHost`, which wrangler ≥ 4.157's types require (#114).

- `UiPlugin.homeCards` (`{ id, Component, guard?, order? }[]`) is Home's "what needs doing" section, above the quick links, rendered by the new `ui/components/PluginHomeCards.tsx`: ordered by `order`, plugin id, card id, each behind its guard, `Suspense` and error boundary (`docs/CONCEPTS.md` §16).
- `RequestCtx.embeddable(contentType)` lets a plugin route opt one response into `SAMEORIGIN` / `frame-ancestors 'self'` — the flag `/api/files/:id` sets — for an `EMBEDDABLE_MIME_TYPES` type only; it answers whether it applied.
- `ServerPlugin.uploadLimits` (`{ '/api/<id>/upload': bytes }`) gives an exact path a non-JSON body cap above `uploadPaths`' 10 MB, up to `MAX_PLUGIN_UPLOAD_LIMIT_BYTES` (50 MiB, clamped), checked first in `apiBodyLimit`; `uploadLimitIssues` (`tests/helpers/plugins.ts`) refuses a bad one.
- `QuickLink` and `CORE_QUICK_LINKS` moved from `ui/pages/Home.tsx` to the leaf `ui/pages/home-links.ts`, so `useNavigationEntries` and `@/plugins/api/ui` no longer pull the Home page into `apps/evals`' typecheck (#178); `tests/config/plugin-ui-kit-graph.test.ts` holds it.
- `makeRequestCtx` (`@testkit/unit`) implements `embeddable` and records the answer on `framed`.

## How to apply

1. If `.rocketflare.json` `neverPort` lists `scripts/lib/rename-lib.mjs` and `scripts/lib/rename-lib.d.mts`, delete both entries, then copy both files from the release: `git --git-dir .upgrade/kit.git show <version>:scripts/lib/rename-lib.mjs > scripts/lib/rename-lib.mjs` (and the same for `rename-lib.d.mts`). Your copy's upgrader planned this jump and still skipped them; from the next release on, both arrive by themselves.
2. Take the kit's version of `scripts/upgrade.mjs`, `scripts/lib/upgrade-lib.{mjs,d.mts}`, `scripts/lib/plugin-lib.{mjs,d.mts}`, `scripts/plugin.mjs`, `scripts/lib/test-plan.{mjs,d.mts}`, `scripts/test.mjs`, `scripts/security-sandbox.mjs` and `apps/web/docker-compose.security.yml` (its `${SECURITY_PG_PORT:-5433}` in `command:` and the healthcheck); resolve any reject in these files in the kit's favour, since they are kit tooling.
3. If your copy moved its test ports, check `apps/web/docker-compose.test.yml`'s `ports:` and `apps/web/.env.test`'s `DATABASE_URL` / `APP_DATABASE_URL` name the same Postgres port: `pnpm test` now refuses a mismatch.
4. Add `mapVirtualHost() { throw … }` to the object `createExecutionContext()` returns in `apps/web/tests/mocks/bindings.ts`, or keep the workaround you already have.
5. If an earlier `pnpm plugin upgrade` left a core-edit line twice (two `'@nivo/heatmap'` keys in `apps/web/vite.config.ts`), delete the wrapped copy by hand once; the next `plugin upgrade` will not add it again.
6. Add `apps/web/src/ui/pages/home-links.ts` with `QuickLink` and `CORE_QUICK_LINKS`, keeping your own Home links in that list, and delete both from `apps/web/src/ui/pages/Home.tsx`, which imports them from `./home-links`.
7. Point the `CORE_QUICK_LINKS` import in `apps/web/src/ui/hooks/useNavigationEntries.ts`, and the `QuickLink` imports in `apps/web/src/plugins/types.ts` and `apps/web/src/plugins/api/ui-wiring.ts`, at `ui/pages/home-links` instead of `ui/pages/Home`.
8. Add `apps/web/src/ui/components/PluginHomeCards.tsx`, add `PluginHomeCard` and `UiPlugin.homeCards` to `apps/web/src/plugins/types.ts`, export `PluginHomeCard` from `apps/web/src/plugins/api/index.ts` and `apps/web/src/plugins/api/ui-wiring.ts`, and render `<PluginHomeCards plugins={uiPlugins} />` above the quick links in `Home.tsx`.
9. Add `embeddable(contentType)` to `RequestCtx` and to `requestCtx` in `apps/web/src/plugins/api/http.ts`, and to `makeRequestCtx` in `apps/web/tests/kit/unit.ts` (with the `framed` getter).
10. Add `MAX_PLUGIN_UPLOAD_LIMIT_BYTES`, `UploadLimit`, `pluginUploadLimits` and `apiBodyLimit`'s third parameter to `apps/web/src/api/middleware/body-limit.ts`, add `ServerPlugin.uploadLimits` to `apps/web/src/plugins/types.ts`, and pass `pluginUploadLimits(serverPlugins)` as the third argument of `apiBodyLimit` in `apps/web/src/api/index.ts`.
11. Add `uploadLimitIssues` to `apps/web/tests/helpers/plugins.ts` and port its case in `apps/web/tests/config/plugins.test.ts`, the "plugin upload limits" block in `apps/web/tests/config/public-mounts.test.ts`, the `embeddable` block in `apps/web/tests/api/plugin-request-ctx.test.ts`, `apps/web/tests/ui/plugin-home-cards.test.tsx` and `apps/web/tests/config/plugin-ui-kit-graph.test.ts`.
12. If you carried a local `homeCards`, `embeddable()` or upload-cap seam of your own, move its plugins onto these and delete the local version.

## Conflicts to expect

- `apps/web/src/ui/pages/Home.tsx` → the quick links moved out and the cards section came in → keep your own sections and links (the links in `home-links.ts`).
- `apps/web/src/plugins/types.ts` → two new fields and one new interface → keep both sides.
- `scripts/lib/rename-lib.mjs` → arrives verbatim for the first time since your copy was made → take the kit's; the rename never translated it.
