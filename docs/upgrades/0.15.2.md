## What changed

Renaming now keeps `rocketflare-dev/` references upstream, names the test Compose project per app, and gives a hyphenated slug the `<snake>_` API-key prefix and a green gate, which a new CI job proves on every pull request.

- `scripts/lib/rename-lib.mjs`: `KIT.preservedPattern` protects the `rocketflare-dev` org and any `rocketflare-dev/<repo>`, replacing the single `github.com/rocketflare-dev/rocketflare` literal; container names such as `rocketflare-dev-postgres` still move. `pnpm kit:upgrade` translates diffs with the same function, so later releases keep the references too (#37).
- `apps/web/tests/config/rename-lib.test.ts` renames every tracked file in memory and fails on any `<slug>-dev/` or `ghcr.io/<slug>` left behind.
- `apps/web/tests/config/update-check-lib.test.ts` passes in a renamed copy: it expects the real manifest to be skipped only when its `app` is `null`, and matches `no .rocketflare.json` as a plain string (a regex spelling of it was renamed).
- `.github/workflows/plugin-ci.yml` stages the installed plugin (`git add -A`) before the gate, so the kit's `git ls-files` scanners check a plugin's files in CI as they do in an app (rocketflare-plugins#8).
- `apps/web/docker-compose.test.yml` sets `name: rocketflare-test` (renamed with the slug), where the project used to be `web` in every copy (#38). The test port stays 5433 ([`docs/CONCEPTS.md` §4 known gaps](../CONCEPTS.md)).
- `apps/web/src/api/utils/core/hash.ts`: `API_KEY_PREFIX` is `'rocketflare_'`, separator included, and `generateApiKey` no longer adds a `_`; the bare name renamed to `my-app`, so a hyphenated copy minted `my-app_…` keys and failed its key tests.
- `scripts/rename.mjs` warns when `API_KEY_PREFIX` does not come out as `<snake>_` (`readStringConstant` in `rename-lib.mjs`), and regenerates `docs/plugin-api.md`, whose summaries are cut at a width the new name moves.
- `apps/web/tests/config/rename-safe-identifiers.test.ts` fails on a bare kit-name string literal in source outside five listed files, where the slug form is the right value.
- `.github/workflows/gate.yml` takes a `rename` input, and `ci.yml`'s new `renamed` job runs the whole gate on the checkout renamed to `my-app` (kit repository only).

## How to apply

1. Accept the kit's `scripts/lib/rename-lib.mjs`, `scripts/lib/rename-lib.d.mts`, `scripts/rename.mjs` and `apps/web/tests/config/rename-lib.test.ts` unchanged; all four are on the rename's exclusion list and keep the kit's own name.
2. If the app was renamed at 0.15.0 or earlier, find the org references that rename rewrote with `git grep -nE '<slug>-dev/|ghcr\.io/<slug>-dev'` (use the app's slug) and change each one back to `rocketflare-dev/<the kit's repo name>`: `ghcr.io/rocketflare-dev/local-neon-proxy` in `apps/web/docker-compose.dev.yml`, `apps/web/docker-compose.test.yml`, `apps/web/docker/Dockerfile.neon-proxy`, `.claude/rules/database.md` and `docs/NEON-DRIVER.md`; `rocketflare-dev/rocketflare-plugins` in `.github/workflows/notify-plugins.yml`; `rocketflare-dev/rocketflare/.github/workflows/plugin-ci.yml` in `.github/workflows/plugin-ci.yml` and `docs/DEPLOY.md`; `rocketflare-dev/rocketflare-plugin-analytics` in `docs/CONCEPTS.md`.
3. In `apps/web/tests/config/update-check-lib.test.ts`, accept the kit's version of the test that reads the real `.rocketflare.json`, and the `toContain('no .rocketflare.json')` assertion that replaces the `/no \.<slug>/` regex.
4. Accept the kit's `.github/workflows/plugin-ci.yml` if the app keeps that workflow (it proves plugins authored in the app's own repositories).
5. Add `name: <slug>-test` above `services:` in `apps/web/docker-compose.test.yml`, using the app's slug.
6. Remove the test container that belonged to the old `web` project once, or the next `pnpm test:db:up` stops on a container-name conflict: `docker rm -f <slug>-test-postgres <slug>-test-neon-proxy`, then `pnpm test:db:up`. Its data is throwaway; the tests migrate a fresh database.
7. In `apps/web/src/api/utils/core/hash.ts`, set `API_KEY_PREFIX` to the app's snake name followed by `_` (`'my_app_'` for `my-app`, `'acme_'` for `acme`) and change the key template in `generateApiKey` from `${prefix}_${randomToken(32)}` to `${prefix}${randomToken(32)}`. Keys already issued keep working, because a key is looked up by its hash.
8. Accept the kit's `apps/web/tests/config/rename-safe-identifiers.test.ts`, which now also fails on a bare kit-name string literal in source outside its `BARE_LITERAL_ALLOWED` list.
9. Accept the kit's `.github/workflows/gate.yml` (the `rename` input) and, optionally, the `renamed` job in `.github/workflows/ci.yml`; the job runs only in `rocketflare-dev/rocketflare`, so in the app it is always skipped.
10. Run `node scripts/plugin-api-doc.mjs` and commit `docs/plugin-api.md` if it changed.

## Conflicts to expect

- `apps/web/docker-compose.test.yml` → a top-level `name:` added above `services:` → keep it, with the app's slug.
- `apps/web/src/api/utils/core/hash.ts` → `API_KEY_PREFIX` gains its `_` and the key template loses one → keep the app's snake name in the prefix.

1. `git grep -nE '<slug>-dev/|ghcr\.io/<slug>-dev'` (with the app's slug) prints nothing.

4. `grep -n "API_KEY_PREFIX = " apps/web/src/api/utils/core/hash.ts` shows the app's snake name followed by `_`.
5. `pnpm web test:api` passes, including `tests/api/keys.test.ts` and `tests/api/auth-cli.test.ts`.
6. `node scripts/plugin-api-doc.mjs --check` exits 0.
