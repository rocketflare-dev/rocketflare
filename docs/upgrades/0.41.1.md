## What changed

Fixes from a field report on a copy built on 0.40.0: the offline switch leaves tracked files alone, `kit:upgrade` honours `--apply-deletes`, ports the vendored plugin and stages its work, and test, docs and migration failures explain themselves.

- The local Workers AI switch moved out of git: `DEV_WORKERS_AI=off` (shell, then `apps/web/.dev.vars`) runs every local `wrangler dev` from `apps/web/.wrangler.offline.toml`, a git-ignored copy of `wrangler.toml` without `[ai]`, regenerated at each launch (`scripts/lib/dev-ai.mjs`). The tracked tomls and `worker-configuration.d.ts` are identical online or offline. Rationale: `docs/CONCEPTS.md` "Local Workers AI switch".
- `pnpm bootstrap --offline` writes `DEV_WORKERS_AI=off`, `--online` writes `on`; neither edits a toml. Any bootstrap run restores an `[ai]` block an earlier release commented out of both tomls and, without `--online`, carries that choice into `.dev.vars`. A run with `DEV_WORKERS_AI=off` already set skips `wrangler whoami`.
- `pnpm dev` (`scripts/dev-server.mjs`) and `pnpm dev:api` (now `node scripts/wrangler-dev.mjs`, which `pnpm dev:tunnel` reaches through it) pass `--config .wrangler.offline.toml` when the switch is off. `pnpm preflight` fails a toml whose `[ai]` block is still commented out, naming `pnpm bootstrap --offline` as the fix. `pnpm web agent:replay` reads the switch too.
- `kit:upgrade` without `--apply` (the plan) runs on a dirty tree; only `--apply` refuses one without `--force`.
- `kit:upgrade --apply --apply-deletes` now `git rm`s the files the kit deleted, after the patch and before the stamp (the flag was parsed and never read). The closing summary is worded from the flags given; `--apply-deletes` without `--apply` says it does nothing.
- `kit:upgrade` ports a vendored plugin (the kit's own repository, no subdirectory: `example-feature`) as core instead of skipping it as plugin-owned, which `pnpm plugin upgrade` also refused.
- `kit:upgrade --apply` `git add`s exactly what it wrote, `.rocketflare.json` included; a file with rejects stays unstaged. `--continue` stages the manifest.
- `apps/web/tests/helpers/source-files.ts` lists untracked, non-ignored sources too (`git ls-files --cached --others --exclude-standard`), so the tenant-query scanner no longer skips a new file before its first `git add`, and the allow-list test no longer calls one "not a source file".
- The rename records the package.json scripts it removed with the kit-only files as `kitOnlyScripts` in `.rocketflare.json`; `/rf-agent-docs`'s `check.mjs` expects those to be missing in a copy, so a freshly renamed copy no longer fails on `pnpm kit:release` or `pnpm web test:kit-only` (`docs/CONCEPTS.md` §13).
- A test-database startup failure (no `.env.test` loaded, a migration Postgres refuses) prints as itself through `tests/helpers/startup-error.ts`, called from `tests/setup.ts`, instead of Vite's `TypeError: code.charCodeAt is not a function`.
- `uniqueId()` in `tests/helpers/auth.ts` is slug-safe (`<base36>-<alnum>`), so a `createTestTenant` slug passes `SLUG_RE` in a validated request.
- `schema-invariants.test.ts` names a tenant foreign key's ON DELETE rule in words and its constraint, and says why it must cascade (so `tenant.purge` reaches every row); `.claude/rules/database.md` recommends composite tenant foreign keys `(tenant_id, x_id) → t(tenant_id, id)` with cascade.
- `pnpm db:generate` (`apps/web/scripts/db-generate.ts`) applies every migration to a scratch database on the local dev Postgres whenever drizzle-kit writes one, names the statement Postgres refused in plain words, and drops the scratch database; `pnpm db:generate --check` runs the check alone. It is not in the gate. The drizzle-kit composite-foreign-key-before-UNIQUE gotcha is in `.claude/rules/database.md`.

## How to apply

1. Take `scripts/lib/dev-ai.mjs`, `scripts/lib/dev-ai.d.mts` and `apps/web/scripts/wrangler-dev.mjs`, the `wranglerDevConfigArgs` call in `apps/web/scripts/dev-server.mjs`, and the `stepCloudflare` / `restoreAiBlocks` / `setDevWorkersAi` changes in `scripts/bootstrap.mjs`.
2. In `apps/web/package.json`, change `dev:api` from `… dev-db.mjs env -- wrangler dev --port …` to `… dev-db.mjs env -- node scripts/wrangler-dev.mjs --port …`, keeping every flag after it.
3. Add `apps/web/.wrangler.offline.toml` to the root `.gitignore`, and the commented `# DEV_WORKERS_AI=off` paragraph to `apps/web/.dev.vars.example`.
4. If `git diff apps/web/wrangler.toml apps/web/wrangler.staging.toml` shows the `[ai]` block commented out (a copy that ran `pnpm bootstrap --offline` on an earlier release), run `pnpm bootstrap --offline --no-dev` (or `--online --no-dev` to turn Workers AI on): it uncomments the block in both tomls and writes the choice to `apps/web/.dev.vars`. Then `git checkout -- apps/web/worker-configuration.d.ts` if `pnpm typecheck` had regenerated it without `AI`, and check `git status` lists none of the three files.
5. Do step 4 BEFORE `pnpm kit:upgrade --apply` to this release: `--apply` still needs a clean tree, and an offline copy is only clean once the tomls are restored.
6. Take `scripts/upgrade.mjs` and `scripts/lib/upgrade-lib.mjs`; the upgrader runs from the copy, so the new `--apply-deletes`, staging and vendored-plugin behaviour applies from the upgrade after this one.
7. If an earlier `kit:upgrade` printed "left in place (pass --apply-deletes to remove them)", `git rm` each listed file you have not built on.
8. If an earlier `kit:upgrade` listed `example-feature` files as `skipped-plugin-owned`, port those files from the kit's diff by hand once (translated to your names), or compare `apps/web/src/plugins/example-feature/` with this release's.
9. Take `apps/web/tests/helpers/source-files.ts`. If your app added its own scanner listing `apps/web/src` with a bare `git ls-files`, add `--cached --others --exclude-standard` to it.
10. Add `"kitOnlyScripts": ["kit:release", "test:kit-only"]` at the top level of `.rocketflare.json` by hand (`kit:upgrade` never ports that file), and take `.claude/skills/rf-agent-docs/check.mjs`.
11. Take `apps/web/tests/helpers/startup-error.ts` and wrap `prepareTestDatabase()` in `apps/web/tests/setup.ts` as `prepareTestDatabase().catch(plainStartupError)`.
12. Take the `uniqueId()` and `testTenantSlug` changes in `apps/web/tests/helpers/auth.ts`; a test of yours that relied on `uniqueId()` containing `_` now expects `[a-z0-9]+-[a-z0-9]+`.
13. Add `apps/web/scripts/db-generate.ts` and `apps/web/scripts/lib/migration-check.ts`, and set `"db:generate": "dotenv -e .dev.vars -- tsx scripts/db-generate.ts"` in `apps/web/package.json`.
14. Wherever your schema references another tenant table by a composite `(tenant_id, x_id)` key, give the reference `onDelete: 'cascade'`, run `pnpm db:generate`, read the SQL and run `pnpm db:migrate`; `schema-invariants.test.ts` names any you miss.
