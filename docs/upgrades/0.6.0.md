## What changed

Analytics left the kit: it is `rocketflare-plugin-analytics` 1.0.0 now, a separate repository
installed by `pnpm plugin add` and listed in `.rocketflare.json` `defaultPlugins`, so a fresh clone
still gets dashboards (D31; `docs/CONCEPTS.md` §8 is a pointer, §16 the decision record).

- **The kit is bare.** Chat, agents and knowledge are still core, but the first real subsystem is
  out, and it took `drizzle-cube`, `recharts`, `d3`, `react-grid-layout` and `react-is` with it. A
  kit installed with `--no-plugins` has no `/analytics`, no `/cubejs-api`, no `/mcp`, no
  `15 * * * *` cron and no chart library in either bundle.
- **What moved**: `routes/{cube-api,analytics-pages}.ts` · `api/cubes/**` · `src/dashboards/**` ·
  `services/{dashboard-templates,fact-tables/**}` ·
  `db/schema/{analytics-pages,analytics-page-groups,facts/*}` · `packages/shared/src/analytics.ts` ·
  `ui/{pages,components}/analytics`, the three analytics hooks and the nav item · the
  `refreshFactTables` cron task · the `onTenantCreated` dashboards hook · the `Dashboard` and
  `Analytics` subjects and their grants · the dashboards visibility resource · the demo seed's
  analytics block · and every test that covered them.
- **`pnpm web db:refresh-facts` and `db:check-facts` are gone.** They were `apps/web/scripts/*.ts`,
  which is not a directory a plugin may own. They are `rocketflare analytics refresh-facts` and
  `rocketflare analytics check-facts`: one organisation rather than every tenant, over a route
  rather than a bare `DATABASE_URL`, and the refresh ENQUEUES (`analytics.refresh-facts`) because a
  route never runs long work. `check-facts` keeps the old exit-1-when-stale contract.
- **`UiPlugin.homeLinks` is a new slot** — a plugin may add a Home quick link beside the kit's with
  the same guard object its route uses; `Home.tsx` composes `[...plugins, ...CORE_QUICK_LINKS]`.
- **`ServerPlugin.hooks.onTenantCreated` gains a fourth argument, `features`** — a hook that CREATES
  rows is the sharpest feature door there is. A plugin implementing it must widen its signature,
  though an extra parameter is safe to ignore, so this is source-compatible.
- **`api/services/access-sql.ts` is a new LEAF** holding `AccessScope` and `sharedWithMyGroups`,
  re-exported from `services/access.ts` so no existing importer moves; a plugin's visibility
  resource imports the leaf, because `access.ts` reads the plugin barrel.
- **`VISIBILITY_RESOURCES` became `visibilityResources()`**, a memoised function, for that same
  reason. If you named the const, rename the call.
- **The barrel writer learned Biome's line width** — two plugins in one `as const` tuple stopped
  fitting on 100 columns, and `removeBarrelLine` is documented as the exact inverse of
  `addBarrelLine`.
- **`pnpm plugin check` no longer holds a plugin AUTHORED IN THE KIT to its `requires.kit` range**
  (sidecar-recorded, `isKit`): its floor is always one release ahead of `package.json` until
  `kit:release` runs. In an app, a `--local` plugin is still checked.
- **A plugin's surface always includes `docs/plugins/<id>/**`**, declared or not, because
  `plugin add` copies the plugin's release notes there — otherwise the host is left with files no
  surface classifies and a `remove` that leaves them behind.
- **A plugin repository may carry `scripts/`** — `classifyPluginFile` now treats it as `repo-only`
  beside `.github/` and `package.json`. There is no `pnpm plugin:release`, so an author copies the
  kit's `release.mjs` and the libs it imports into their own repo.
- The `feature-analytics` surface and the three analytics example surfaces are gone from
  `.rocketflare.json`; `upgrade-notes.test.ts` gained a `RETIRED_SURFACE_IDS` list so the released
  0.2.0 and 0.3.0 notes, which name them, are not rewritten.

## How to apply

1. Read the plan, then take the kit release:
   `pnpm kit:upgrade --to 0.6.0`, then `pnpm kit:upgrade --to 0.6.0 --apply`.
2. **To keep analytics, install the plugin BEFORE running `pnpm db:generate`** — this is the whole
   of the migration risk in this release:
   ```bash
   pnpm plugin add https://github.com/rocketflare-dev/rocketflare-plugin-analytics.git@1.0.0
   pnpm plugin add https://github.com/rocketflare-dev/rocketflare-plugin-analytics.git@1.0.0 --apply
   ```
3. Generate and apply the migration, reading the SQL first:
   `pnpm db:generate --name plugin-analytics-1.0.0`, then `pnpm db:migrate`. Verified against the
   real SQL:

   | With the plugin | `analytics_pages` | `analytics_page_groups` | the fact table |
   |---|---|---|---|
   | installed first | no DDL, rows survive | no DDL, rows survive | `DROP` + `CREATE`, renamed |
   | not installed | `DROP TABLE` | `DROP TABLE` | `DROP TABLE` |

   The fact table is renamed under the `<id>_*` rule — `DROP TABLE tenant_activity_daily_facts`
   then `CREATE TABLE analytics_tenant_activity_daily_facts` — so drizzle-kit asks whether it is a
   rename: **answer `create table`**. It is derived data, so the `:15` cron refills it within the
   hour, or `rocketflare analytics refresh-facts` does it now.
4. Ignore `0013_kit-analytics-removed` in the kit's own journal, which drops all three with
   `IF EXISTS`. That is the BARE kit's history and it never runs in your tree, because
   `kit:upgrade` does not copy a kit migration (`docs/CONCEPTS.md` §13) and you generate your own.
5. Add to BOTH wrangler tomls: `[triggers].crons` gains `"15 * * * *"`, and
   `[assets].run_worker_first` gains `"/cubejs-api"`, `"/cubejs-api/*"`, `"/mcp"`, `"/mcp/*"`. The
   parity test reads `API_PREFIXES`, so a forgotten entry fails your gate rather than silently
   serving the app shell to an `<object>` embed. `pnpm provision cloudflare <env>` writes them from
   the installed surface. (`pnpm plugin add` prints steps 5–8 as its plan.)
6. Edit `apps/web/vite.config.ts`: add `'/cubejs-api': proxyTo()` and `'/mcp': proxyTo()` to the dev
   proxy, alias `'@nivo/heatmap'` to `./src/plugins/analytics/ui/lib/nivo-heatmap.tsx`, and add
   `'recharts'` to `resolve.dedupe`.
7. Let `pnpm plugin add` install the plugin's dependencies — they are declared in its manifest.
8. **If you removed analytics instead**, run `pnpm --dir apps/web remove d3 drizzle-cube
   react-grid-layout react-is recharts`, and take the cron, the two prefixes and the Vite lines back
   OUT of those same files.
9. Replace every `pnpm web db:refresh-facts` / `db:check-facts` in your scripts and pipelines with
   `rocketflare analytics refresh-facts` / `rocketflare analytics check-facts`.
10. Widen any `ServerPlugin.hooks.onTenantCreated` of your own to take `features`, or keep three
    parameters and ignore the fourth.

## Conflicts to expect

**Many, and most of them are files that MOVED.** `kit:upgrade` translates a kit diff into your
names; a file the kit deleted and a plugin re-added at a different path is two operations it cannot
pair up.

- `apps/web/src/api/cubes/**`, `apps/web/src/dashboards/**`,
  `apps/web/src/api/routes/{cube-api,analytics-pages}.ts`, `apps/web/src/db/schema/analytics-*`,
  `apps/web/src/db/schema/facts/**`, `packages/shared/src/analytics.ts` and the analytics UI → the
  kit deleted them and the plugin re-adds them elsewhere → resolve every reject by DELETING your
  copy and letting `plugin add` write the plugin's, which is the same code translated the same way.
  Note any customisation of those files first: it is now an edit to the installed plugin's tree,
  which is ordinary source in your repository.
- `api/index.ts` → the two analytics mounts leave the mount table → read rather than take.
- `api/scheduled.ts` → `CORE_SCHEDULED_TASKS` loses the `:15` entry → read rather than take.
- `services/access.ts` → the leaf extraction plus the memoised `visibilityResources()` → read
  rather than take.
- `permissions/abilities.ts`, `packages/shared/src/permissions.ts` → the `Dashboard` and `Analytics`
  subjects leave `CORE_SUBJECTS` → read rather than take.
- `ui/App.tsx`, `ui/components/SideNav.tsx`, `ui/pages/Home.tsx`, `ui/lib/query-keys.ts`,
  `apps/web/scripts/seed.ts`, `apps/web/src/ui/index.css` (the `--dc-*` block leaves) → their
  analytics entries are removed → read rather than take.

## Verify

1. `pnpm lint && pnpm typecheck && pnpm test && pnpm build` is green — and with the plugin
   installed, its own tests run in your projects, including the two-tenant `cube-isolation.test.ts`.
2. `pnpm plugin check` exits 0 and lists `analytics`, and `pnpm plugin list` shows it with its repo
   and pinned version.
3. Signed in: **Analytics** in the nav and on Home, and the seeded **Organisation Overview**
   rendering with live numbers.
4. An unauthenticated `curl -i <host>/cubejs-api/v1/meta` answers a JSON 401 rather than HTML.
5. `rocketflare analytics check-facts` reports the fact table `fresh` and exits 0.
6. `grep -c recharts apps/web/dist/ui/assets/index-*.js` is 0 with or without the plugin, and
   without it `grep -rl drizzle-cube apps/web/dist` finds nothing at all.
7. `REQUIRE_PROVISIONED=1 pnpm web test:config` still passes — that is the check that the cron and
   the two prefixes reached BOTH tomls.
