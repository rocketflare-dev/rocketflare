## What changed

The knowledge base becomes measurable and structure-aware: eval corpora, structured chunks, model-consistent search with re-embedding, dedupe, retry, reranking, metered spend, and typed knowledge facts extracted from documents behind a `knowledge-facts` flag.

Why each part is built the way it is: `docs/CONCEPTS.md` §9 "Knowledge" and "Knowledge facts" (D43).

- Eval corpora under `apps/evals/datasets/<name>/` (`docs/*.md` plus `retrieval.jsonl`, `chat.jsonl`, `entities.jsonl`, `facts.jsonl`, `conflicts.jsonl`, optional `corpus.json`), ingested once with a real embedder (`docs/EVALS.md` § Corpora); `GEMINI_API_KEY` alone is enough to run them.
- New suites `knowledge · retrieval` (`RecallAtK`, `MRR`, `ContextPrecision`; `--rerank none|fireworks|workers-ai`), `knowledge · facts` (`pnpm eval facts`) and `chat · conflicts` (`pnpm eval conflicts`); `chatHarness` takes `corpus` and `prepare`; scorers `factExtractionScore` / `conflictDetectionScore`.
- Chunks are exact slices of the stored text (`char_start`/`char_end`), start and end at markdown headings with the shared `heading_path`, split GFM tables only between rows (`table_header`); heading path and table header are embedded, not stored in the text. Stored text is CRLF → LF.
- Lexical search reads a generated `chunks.search_vector` (GIN) instead of computing `to_tsvector` per query; hits gain `headingPath` and `page` (always null: `toMarkdown` emits no page markers).
- **Behaviour:** every dense leg filters on `chunks.embedding_model` = the query vector's model, so chunks from another model are found by keyword only until re-embedded.
- **Behaviour:** a plain ingest or text upload whose content hash matches a tenant-wide document of the same source answers that document (`200`, `deduplicated: true`) instead of creating a second one; an unchanged `externalId` upsert is `mode: 'unchanged'` (no chunking or embedding).
- Re-embed: job `document.reembed`, `POST /api/ai/documents/reembed` (admin+, `202`), enqueued automatically when a tenant's resolved embeddings model changes; `GET /api/ai/documents/health` counts `staleEmbeddings`.
- `POST /api/ai/documents/:id/retry` re-enqueues a `failed` document; the Documents page shows Retry.
- The jobs consumer dead-letters into `<app>-jobs-dlq` / `<app>-jobs-dlq-staging`; no consumer is bound to it. Inline indexing is an `ingest document` span.
- **Behaviour:** search reranks the top `RERANK_CANDIDATES` (default 20) fused candidates — a tenant `rerank` row (Cohere, Voyage, Fireworks presets, or `workers_ai`), else Workers AI `bge-reranker-base` when `[ai]` is bound, else none — then applies `RERANK_MIN_SCORE` (unset = off); hits gain `rerankScore`, and `rank` is the final order.
- New AI scope `rerank` (`AI_SCOPES`, readiness, Settings → AI → Rerankers with a connection test).
- Knowledge metering: embeddings, rerank and extraction calls write `ai_usage` rows `knowledge.embeddings` / `knowledge.rerank` / `knowledge.extraction`; `KNOWLEDGE_TENANT_DAILY_COST_USD` (unset = no cap) pauses extraction only, until the next UTC day.
- Knowledge facts: contracts `@rocketflare/shared/ai/knowledge-facts`, tables `knowledge_entities` and `knowledge_facts`, the entity-type registry (`APP_ENTITY_TYPES` in the app-owned `api/services/knowledge/entity-types.ts`, empty; `ServerPlugin.knowledgeEntityTypes` for a plugin, a field, not a barrel), and `EntityTypeRegistration` / `defaultEntityResolver` in `@/plugins/api`.
- Job `knowledge.extract`, enqueued when a document's text changed, the tenant has the new core flag `knowledge-facts` (default OFF) and a type is registered: one `submit_facts` call per section (prompt key `knowledge-extract`), quotes verified verbatim, values and dates parsed in code, mentions resolved to a domain row, a staging entity or a possible match.
- Fact states `accepted · unconfirmed · conflicting · superseded · rejected`; a person's confirm or reject survives re-extraction of the same entity, key and value. Nothing writes a domain column.
- Review API `/api/knowledge` (404 with the flag off; CASL subject `KnowledgeFact`, member read + update), tools `lookup_facts` and a `facts` block on `search_knowledge` for flagged tenants, and the chat prompt requires citing every side of a conflict.
- UI behind the flag: the entity page `/knowledge/entities/:type/:id`, "Is this still right?" (Confirm / Not right / Use this one), a "To review" view and nav badge on Knowledge, and an entity card in chat (`CUSTOM kit.entity`).
- `documents.origin` / `reviewer_user_id`: `@/plugins/api` `ingestDocument` / `ingestDocumentFile` set `origin: 'integration'` and take an optional `reviewerUserId`; `PluginIngestResult` gains `deduplicated`.
- The api test projects block outbound network: a request to anything but loopback, `localhost` or `*.localtest.me` fails at once with `OutboundNetworkError` naming the URL.

## Conflicts to expect

- `apps/web/src/api/services/ai/chunking.ts` → rewritten (exact slices, sections, tables) → take the kit's file and re-apply a custom window size through `ChunkOptions`.
- `apps/web/src/api/services/ai/retrieval.ts` → reranks after fusion and renumbers `rank` → a caller that read `rank` as the RRF position reads `score` (still the RRF score).
- `apps/web/src/api/routes/ai-documents.ts` → `/ingest` and `/upload` answer `200` on a duplicate → a client asserting `201` on every ingest must accept `200`.
