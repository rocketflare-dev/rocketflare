# Phase 7 — The run workspace

**Goal:** the run stops being a modal with a `<pre>` in it. Kit-owned, no new dependency.

Build this **against the poll path first** — it must never depend on [phase 6](06-streaming.md).
`useRunStream` stays additive, and deleting it must leave a working page.

```
┌ Agents › Research topic ─────────── [Awaiting input] attempt 1 · 2m 04s ┐
│  ⚠ Action required                              ← pinned, above the fold │
│    "Send this summary to 412 subscribers?"                               │
│    ▸ send_email { subject: …, recipients: 412 }        expires in 6 days │
│    [ Approve ]  [ Reject ]   note ▸                                      │
├──────────────────────────────┬───────────────────────────────────────────┤
│  Timeline                    │  Output · Artifacts · Usage · Input       │
│   ✓ Searching knowledge 1.2s │   ## Answer …                             │
│     ▸ search_knowledge       │   Sources: [doc] [doc]                    │
│       [doc][doc][doc]        │                                           │
│   ⏸ Waiting for approval     │   12 turns · 8.4k tok                     │
│  ─────────────────────────── │                                           │
│  [ send a note to the agent ]│                                           │
└──────────────────────────────┴───────────────────────────────────────────┘
```

The action panel is **above** the timeline, not inside it: somebody arriving from a notification is
here to decide, not to read. It unmounts the moment the run is not `awaiting_input`.

## Shell

`/agents/runs/:runId` keeps its URL and becomes a lazy `RunPage.tsx` with its own route — the
`['/agents','/agents/runs/:runId'].map(...)` at `App.tsx:131` collapses to two plain routes. Guard
`read AgentRun`, `PageHeader` + breadcrumb.

**Deleted:** `RunDetailDrawer.tsx`, `AgentSteps.tsx`. `formatDuration` / `runDuration` move to
`ui/lib/format.ts` (`AgentsPage` imports them from the drawer today — a real coupling).

New tree under `pages/agents/`: `run/{RunHeader,ActionRequiredPanel,RunErrorAlert,SteerComposer}`,
`run/interrupts/*` (kind dispatch, one component per kind, `ToolCallPreview`, a pure `expiry.ts`),
`run/timeline/*` (`timelineModel.ts` pure, `RunTimeline`, `TimelineGroup`, `TimelineRow`,
`ToolCallRow`, `toolResults.tsx`, `useStickToBottom.ts`), `run/output/*`, `outputs/*`, `fields/*`.

`Row` / `Section` / `formatCost` are extracted from `ChatStatsPanel.tsx` into
**`components/ai/StatRows.tsx`** — a legal markdown zone whose consumers are both lazy, so Vite
emits it once. `components/shared` would be the mistake (eager barrel).

Small cleanups worth doing here: `AgentsPage` rows become real `<Link>`s so middle-click and
open-in-new-tab work (half the point of leaving the modal), and `STATUS_LABELS` — duplicated at
`AgentsPage.tsx:34` and in `RunStatusBadge` — becomes one export, because the
`Record<AgentRunStatus, string>` exhaustiveness is what tells you both places need the new key.

Layout: action panel full-width and `sticky top-0`; below it
`lg:grid-cols-[minmax(0,26rem)_minmax(0,1fr)]`. Under `lg` they stack **tabs first, timeline
second** — on a phone the answer is what people came for. `run.error` renders above the tab bar,
always: **a failure is not a tab.**

## The action panel

Kind dispatch is an exhaustive `switch` over the shared union, so a fifth kind is a type error until
it has a branch. Validation parses the draft with the kind's shared zod schema first; the server's
400 `details` map back through the existing `fieldErrorFor` / `FieldError` (lift
`RunAgentModal.issuesFrom` to `pages/agents/issues.ts` so both use one copy). No optimistic write —
this is a decision with a side effect.

Four details that matter:

- **409 is information, not an error.** `isInterruptNotPending(error)` mirrors
  `isAgentRunsNotConfigured`; the panel swaps to `alert-info` — *"Someone else answered this"* — and
  refetches. No toast, no red.
- **Expiry ticks at a rate a pure function chooses.** `expiryState(expiresAt, now)` returns
  `tickMs`: 1 s under an hour, 60 s under a day, **`null` beyond**. A naive 1 s countdown on a
  seven-day expiry re-renders the panel ~600,000 times.
- **A non-approver sees no buttons, not disabled ones** — they still see the panel, because they
  need to know the run is blocked and on whom. One line instead: *"Waiting for an administrator to
  approve."* A disabled control with a tooltip is how you tell a member they are second-class.
- **Focus the heading on mount, never Approve.** An autofocused destructive button plus a stray
  Enter is how 412 subscribers get an email. `role="region"` + `aria-live="polite"` so a run that
  parks while you are watching announces itself.

## The timeline

Two pure stages in `timelineModel.ts`: `buildTimeline(events)` then `groupTimeline(rows)`, plus
selectors (`selectArtifacts`, `selectInterrupts`, `selectUsage`, `defaultExpanded`, `windowGroups`).

> **Everything the right pane shows that is not `run.output` is a selector over the same rows —
> never a second fetch.**

Two corrections to the existing reducer, both load-bearing:

- **`tool.end` currently overwrites `at`** (`AgentSteps.tsx:128`), destroying the start time — which
  is exactly why per-call duration is impossible today. Keep `at` as the start; add `endedAt` /
  `durationMs`.
- **Make it idempotent under duplicate events.** Once a stream and a fetch both feed it the same
  event can arrive twice and the FIFO `openTools` map would double-push. Dedupe by `event.id`.

Grouping rule, stated so it is testable: a `running` step opens a group, subsequent non-step rows
attach, a matching `done|error` step closes it, a **different** step key implicitly closes the open
one (an unclosed step is a real state, shown spinning). Rows before the first step go to
`__preamble__`, rows after the last to `__tail__` — that is where a settled run's trailing
`status` / `error` / `interrupt` rows live, and they must not be swallowed by the last step.

Rendering: collapsed groups read `✓ Searching knowledge · 1.4s · 3 tools`; expansion is
`defaultExpanded` XOR a local `Set` of user toggles, so a new event never yanks open a group the
reader deliberately closed.

**Real tool results for free — do not write parsers.**
`documentCardsFromToolResult(name, result)` already exists in `@rocketflare/shared/ai/embeddings`
and is documented as serving the agent-run projection. So `search_knowledge` / `list_documents` →
a `DocumentCard` strip, and `get_document` → the card whose excerpt is the window the model saw.
Unknown tools keep `<details><pre>`, truncated at ~4 000 chars (a 200 KB tool result pretty-printed
into the DOM is a real hang).

An interrupt appears **both** pinned (to act) and inline at its seq (to read history) — but **the
form exists only in the pinned copy**; two live forms for one decision is the trap.

Auto-scroll is `useStickToBottom` over an `IntersectionObserver` sentinel, firing only when
`atBottom` **and the last row id changed** — keying on height yanks the reader down whenever they
expand an old group. Otherwise a floating `Jump to latest · 4 new` pill.

For long runs, **window, do not virtualise**: 40 groups from the end with `Show earlier activity ·
312 events`. Row heights vary wildly (markdown, card strips, `<pre>`), so a virtualiser needs
measurement, which fights both auto-scroll and collapsing. If runs ever get truly huge the answer is
server-side pagination of `events` by `seq`.

## The right pane

**`URLTabs` (`?tab=output|artifacts|usage|input`), not stacked panels.** Stacking makes the
approver — the person this feature exists for — scroll past the answer to reach the artifact they
must inspect. `URLTabs` already carries a `badge` (`Artifacts · 3`) and writes `replace: true`.

**`outputs/` mirrors `forms/`**: `outputFor(agentKey) → { schema, Component, artifacts? }`, killing
the hard-coded `agentKey === 'summarize-text'` branches. The doc comment says what `forms/index.ts`
says: **an agent = one shared input schema + one `forms/` entry + one `outputs/` entry.** Two
registries keyed the same way is the right amount of ceremony; one combined map would make the run
*modal* chunk and the run *page* chunk pull each other's components.

**Artifacts** come from the table ([phase 2](02-schema.md)), with `outputFor().artifacts?.(output)`
as the zero-server-change fallback for an agent that declares none.

**Usage, and an honest gap.** Reads `GET /runs/:id/stats` (gated `manage AiConfig`, mirroring
`/conversations/:id/stats`) once `ai_usage.agent_run_id` is populated. Until then it shows what the
rows genuinely know — attempts, steps, tool calls, errors, wall-clock, per-step durations — and
**says in words** that model cost is not attributed per run in this deployment, rather than
rendering `$0.00`. That is the `unpricedTurns` honesty rule copied across.

## Finding what is waiting

**The sharpest UI trap.** `isRunActive` widens to include `awaiting_input` because the exclusive
index depends on it — and that instantly makes three call sites wrong:

- `runPollInterval` would poll a parked run every 3 s **for a week**
- the list's `refetchInterval` likewise
- `RunStatusBadge`'s `animate-pulse` + `aria-live` would pulse and announce for seven days

Add **`runOwesAnswer(status) = queued || running`** and point all three at it. `isRunActive` keeps
its meaning ("this agent is busy") and drives the exclusivity copy only.

Then:

- `RunStatusBadge` gains `awaiting_input` → "Awaiting input", `PauseCircleIcon`, a new warning tone
  token, **no pulse**. The status filter picks it up free from `agentRunStatusSchema.options`.
- `/agents?awaiting=1` chip — which means moving `RunsTable`'s filters from `useState` to
  `useSearchParams`. Worth doing now, since the badge and the notification both link to it.
- **SideNav badge.** `navigationConfig` is a static const consumed by the pure, tested
  `filterNavConfig`, so do **not** make it a hook — add `badgeKey?` / `badgeTone?` to `NavItem` and
  resolve them in `SideNav` via a small `useNavBadges()`. Fed by
  `GET /interrupts?status=pending&pageSize=1` → `pagination.total`, keyed `['agent-run','awaiting']`
  so the existing nudge covers it. **Never polled.** Render warning tone rather than today's
  `text-xs text-muted`, and **when the nav is collapsed render a dot on the icon**, or the whole
  feature is invisible to everyone who collapsed the sidebar.

**Notification deep links do not exist yet.** Issue #17 says *"the bell already carries the
notification; its `data` links to the run page"* — **that is wrong.** `NotificationsBell.tsx` links
to `/notifications` wholesale and neither it nor `pages/Notifications.tsx` reads `data` at all. Add
a small `notificationLink(notification)` helper (`type` + `data` → a path, unknown → null) used by
both surfaces — worth doing regardless, since `access_request_decided` and `member.joined` are
equally undeep-linked today.

## One field renderer, two callers

`agentInfoSchema` gains `inputJsonSchema`, produced server-side by the existing
`toolInputSchema(meta.inputSchema)` (`kit.ts:98`). Three reasons: the conversion already exists; it
keeps zod off the client, preserving the zod-3/zod-4 boundary from #16; and it is **the same shape
`Interrupt.responseSchema` carries**, so one renderer serves the unregistered-agent run form *and*
the `form` interrupt kind — which is why the `form` kind then costs almost nothing.

`fields/schemaFields.ts` is pure: `fieldsFromJsonSchema(schema) → FieldSpec[] | null`, supporting a
top-level object of string / number / boolean / enum / string-array with `required`, `title`,
`description`, `default` and the min/max keywords.

> **`$ref`, `allOf`/`anyOf`/`oneOf`, nested objects and tuples return `null`, and the form falls
> back to the JSON textarea *whole, never per-field*.** A form that silently drops a field the agent
> requires is worse than a JSON box, and that failure is invisible until a run 400s.

`formFor` becomes three rungs: registered form → `schemaForm(inputJsonSchema)` → `jsonForm`.

## Conventions that constrain all of this

Server data only in the TanStack cache under a `query-keys.ts` key parsed with the shared zod
schema; zustand is websocket state only; design tokens not raw palette utilities; Heroicons only;
**Markdown may only be imported under `pages/agents|chat/` or `components/ai/`** and
`components/shared` must stay markdown-free (`tests/config/ui-bundle.test.ts` asserts it).
